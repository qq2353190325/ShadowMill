# 00 · 项目结构

> 本文件描述 ShadowMill（影坊）的整体工程结构：技术栈、仓库顶层目录、`src/` 目录树、构建与打包配置、运行时数据目录与全局约定。

---

## 1. 项目概览

**ShadowMill（影坊）** 是一个基于 Electron 的桌面应用，以「项目」为粒度，把音视频创作拆成五个可独立执行的节点，串成一条完整流水线：

```
① 音色管理  →  ② 文字生音频  →  ③ 文字转字幕  →  ④ 字幕生成 HTML  →  ⑤ 视频预览
（克隆/留档音色） （Qwen-TTS 合成） （whisper.cpp 转录 或 手写/脚本生成） （自定义模型 Agent 生成 + 转视频） （播放 / 定位成品 MP4）
```

- 每个「项目」对应磁盘上一个目录，统一存放字幕、内容脚本、HTML、音频与视频产物。
- 语音识别（whisper.cpp）与视频渲染（HyperFrames + FFmpeg）都在**本机**完成，不消耗 API 额度。
- HTML 动画页面不由应用内置模板生成，而是交由**用户自配置的 OpenAI 兼容模型 Agent** 流式生成/修改。

## 2. 技术栈与版本

| 分层 | 技术 | 版本（见 `package.json`） | 说明 |
|---|---|---|---|
| 运行时 | Electron | `44.7.0` | 主进程 + 渲染进程（Chromium 152 + Node 24.21.0），`sandboxed preload` 要求 CJS |
| 渲染层 | Vue | `^3.5.43` | SFC（`<script setup lang="ts">`），无 vue-router / pinia |
| 构建 | electron-vite | `^5.0.0` | 三端（main / preload / renderer）分别构建 |
| 构建 | Vite | `^7.3.6` | 渲染层 dev server 固定 `127.0.0.1:5173`（`strictPort`） |
| 构建 | @vitejs/plugin-vue | `^6.0.9` | SFC 预编译（禁止运行时模板编译，配合 CSP） |
| 语言 | TypeScript | `^7.0.2` | 全量 TS（主进程 / preload / 渲染层 / agent） |
| 打包 | electron-builder | `^26.15.3` | 目标：Windows x64 NSIS 安装包 |
| 依赖 | openai | `^7.15.0` | OpenAI 兼容客户端（HTML Agent、连接测试） |
| 依赖 | opencc-js | `^1.4.2` | 繁体→简体转换（whisper 转录结果后处理，懒加载） |

> 架构决策：**不加 `"type": "module"`**，main/preload 输出 CJS，以适配 Electron 的 sandboxed preload；因而不引入 `vue-tsc`，SFC 语法由构建兜底，类型检查用 `tsc --noEmit`。

构建产物与源码的对应关系：

```
src/main/index.ts      → out/main/index.js        （CJS，externalize 依赖）
src/preload/index.ts   → out/preload/index.js     （CJS）
src/renderer/          → out/renderer/            （index.html + assets/*，base './' 相对路径）

- `electron.vite.config.ts` 中 main/preload 使用 `externalizeDepsPlugin()`，把 `openai` / `opencc-js` / `electron-updater` 保留为运行时 `require`，再由 electron-builder 按 `dependencies` 自动收集进 asar（`build.files` 只排除构建期包，见 [root/package.json.md](./files/root/package.json.md) §5.1）。

- `vendor/**/*` 同样经 `build.files` 进 asar：`vendor/gsap/gsap.min.js` 由 `hfEnv.findLocalGsap()` 以 `app.getAppPath()` 定位（dev = 项目根，打包后 = `app.asar` 根），主进程只读字节与复制，**不需要 `extraResources`**；该目录未被 `.gitignore` 忽略，属受版本控制的分发资源。项目内的 HTML 统一引 `./gsap.min.js`（离线可用），而**导出/下载单个 HTML 时**由 `hfEnv.externalizeGsapHtml()` 换回固定版本 CDN 地址（与该随包文件版本一致），避免导出物缺同目录文件导致动画不跑。
- 渲染层别名：`@renderer` → `src/renderer/src`，`@shared` → `src/shared`，并在 `tsconfig.web.json` 的 `paths` 中同步声明。
- dev 专属插件 `cspDevWsPlugin` 在 `transformIndexHtml` 阶段把实际 dev server 的 `ws://…` 源注入 CSP 的 `connect-src`，避免端口漂移导致 HMR 被静默拦截。
- 品牌相关两个构建期动作（都在 `electron.vite.config.ts`）：`brandHtmlPlugin()` 把 `%APP_NAME%` / `%APP_NAME_EN%` / `%APP_SLOGAN_SHORT%` 替换成 `src/shared/constants.ts` 的值（`order: 'pre'`，早于 Vite 自带的 `%VITE_*%` 替换）；`checkBrandConsistency()` 读 `package.json` 的 `build.productName`，与 `APP_NAME_EN` 不一致时 `console.warn('[dsh:brand] …')`。

## 7. 运行时数据目录（userData）

**位置保持 Electron 默认**：`const USER_DATA_DIR = app.getPath('userData')`，即 **`%APPDATA%\<package.json 的 name>`**（现为 `%APPDATA%\shadowmill`）。`src/main/index.ts` **刻意不调用 `app.setPath('userData', …)`**，目录名继续跟随 `name`。应用运行期产生的数据全部落在该目录下，仓库/打包目录保持只读：

```
%APPDATA%\<package.json 的 name>\      # 现为 %APPDATA%\shadowmill

> **历史数据目录（品牌改名）怎么处理（2026-10 定稿，本轮改为「界面在渲染层」）**：改名（`my-app` → `shadowmill`）会让目录名改变，老用户打开应用会看到「项目全没了」——数据其实还在 `%APPDATA%\my-app` 里。现在的做法是**扫描 + 弹窗让用户决定，绝不静默迁移**：
> 1. `findLegacyData()` 扫 `LEGACY_DIR_NAMES`（现为 `['my-app']`），四道闸依次为「排除自身 → 目录存在 → **归属证明通过** → 白名单条目确有数据（空壳不打扰）」；`OWN_DATA_ENTRIES = ['projects','whisper','voice','tts-output','html-agent','settings.json']`。扫描结果由 `legacyInfo()` **扫一次即缓存**（`MIGRATE_USER_DATA=0` 时整段关闭）。
> 2. **归属证明（`isOurs`）**：`my-app` 这种名字太通用，`%APPDATA%` 下可能有别的应用也叫这个，所以先证明「它是我们的」——① 目录里**任意一个点开头的标记文件（名字不限）**内容里的 `appId === 'com.shadowmill.app'`（`hasOurIdentity()` **只看内容、不猜文件名**：标记名随历次品牌 / 目录名变化，按固定候选名尝试无法穷举，会静默漏掉自己的老目录）；② 否则看结构特征 `<目录>\projects\<项目名>\project.json` 是否存在（照顾标记机制上线之前的历史目录）。两条都不满足就**不提示、不迁移**。
> 3. **契约与界面分工**：主进程只提供 `legacy:status`（返回 `LegacyDataInfo | null`：老目录绝对路径 / 确有数据的条目名 / 项目数）与 `legacy:resolve`（载荷是 `'migrate' | 'delete' | 'later'`，非法或缺省一律当 `'later'`），**不做任何界面展示**；渲染层外壳挂载时问一次 `legacy:status`，有结果就弹**应用内弹窗**（`LegacyDataDialog.vue`，沿用 `.hf-modal` 体系），用户在弹窗里选「迁移过来 / 删除旧数据 / 稍后再说」。**不再使用原生 `dialog.showMessageBox`**（与 Cyber UI 设计系统不一致），也**删掉了原先建窗后 1.5s 的延迟**（显示时机由渲染层掌握，主进程侧不需要「等首屏」的魔法数字）。
> 4. **执行语义**：迁移 = 白名单逐项移动（目标不存在时整条目 `renameSync`，否则递归合并、**文件已存在一律跳过**；`settings.json` 唯一例外——只有新文件仍是「出厂状态」才覆盖并先备份成 `.before-migrate.bak`），返回 `{ moved, skipped, failed }` 且**只有 `failed === 0` 才清缓存**（有失败可重试），结果由渲染层 toast 呈现；删除 = **先二次校验**目标确为 `%APPDATA%` 下、名字在清单里的目录，再 `rmSync`，成功后清缓存；「稍后再说」只写日志，**下次启动再问**。自测可用 `MIGRATE_USER_DATA=0` 关掉整段功能。
> 5. **⚠ 代价**：`LEGACY_DIR_NAMES` 是手工清单，**没有任何自动发现机制**——以后再改 `package.json` 的 `name`，**必须**把旧名字加进去，否则用户又会看到「项目全没了」。
>
> 详见 [main/index.ts.md](./files/main/index.ts.md) §3.1。

> 项目**只有** `userData/projects/<项目名>/` 一种形态：每个项目都是用户自己创建、可读可写的普通项目；界面上的项目入口只有顶部「工作项目」栏与首页「我的项目」卡片。

## 8. 全局约定与约束

1. **IPC 契约不可变**：频道名集中在 `src/shared/ipc.ts`（10 分组 / **85** 频道），载荷格式与 `src/preload/index.ts` 的 11 个命名空间方法签名一一对应；重构期间要求「线上载荷一个字节不改」。
2. **preload 必须 CJS**：全工程不设 `"type": "module"`，`src/agent/package.json` 单独声明 ESM 以免影响主工程输出。
3. **安全边界**：`contextIsolation: true`、`nodeIntegration: false`；渲染层无 `clipboard` 模块，复制经 `app:copy-text` IPC；预览 iframe 使用 `sandbox="allow-scripts allow-same-origin"`；字幕等文本一律 `textContent` / `escTxt` 写入防注入。
4. **本地文件访问经自定义协议**：dev 下渲染层来自 `http://127.0.0.1:5173`，Chromium 会拦截 `file://` iframe，因此 HTML 预览统一走 `hgpreview://p/<项目名>/<相对路径>`，由主进程做目录穿越校验后返回（`rangeResponse()`：支持 `Range` 字节范围取 → `206` / `416`，基础头带 `Accept-Ranges: bytes`，响应体是文件流；媒体预览的可跳转性依赖它）。
5. **CSP 静态声明 + dev 动态补 ws**：`index.html` 的 meta CSP 不允许运行时模板编译，故 SFC 全部预编译。
6. **视觉设计系统**：深空科技主题（`#0B1220` 主背景 / `#00D4FF` 主色）由 `src/renderer/src/assets/main.css` 统一承载，组件按需 scoped 补充。
7. **两类字符串分属两层，不要混用**：**品牌文案**（应用名 / 英文名 / 口号）放 `src/shared/constants.ts`（三端共用，可随品牌改名；`index.html` 走占位符注入、`package.json` 走构建期校验）；**渲染层 `localStorage` 键名**放 `src/renderer/src/constants.ts`（**故意不跟随品牌改名**，改了会丢老用户记忆，必须补迁移）。两处都不要在页面里写裸字面量。
8. **userData 路径一律惰性求值（纯保险）**：`projects.projectsRoot()` / `whisper.modelsDir()` / `runtime.runtimeDir()`（`runtimeRoot()` 已随分包删除，各包根用 `runtime.packRoots()`） / `settings.settingsFile()` 都写成函数 / getter。当前 userData 位置只跟随 `package.json` 的 `name`，模块级快照本来也正确；但将来若有人重新引入 `app.setPath` 之类的改动，快照会因 ESM import 提升而静默钉在当时的位置（症状就是品牌改名后「项目全没了」）。函数化零代价，不要退化成常量。
9. **改 `package.json` 的 `name` 必须手动登记旧目录名**：userData 目录名仍跟随 `name`，`src/main/index.ts` 的 `LEGACY_DIR_NAMES`（现为 `['my-app']`）是**唯一**的发现机制，没有任何自动发现；忘了加，老用户就会看到「项目全没了」。目录内的 `.shadowmill-data`（`appId`）是扫描时的**归属证明**，不是自动认领机制（见 §7）。
10. **改代码前先看 CHANGELOG 当前版本区块，改完追加一条，改两次算完整版**：动任何源码前先看根目录 `CHANGELOG.md` 最上面的当前版本区块（这一版已经改了什么，避免重复实现），改完必须在**当前版本区块**追加或更新一条记录（`[标签]` + 影响范围 + 验证方式）；同一功能在本版内改到第 2 次的，在最新那一条标 `[完整版]`，仍在演进中的标 `[待续]`——详细规则见根 `agents.md` 第三节与关键约定 3、4，漏记视同改动未完成。
