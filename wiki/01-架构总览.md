# 01 · 架构总览

> 本文件描述应用的跨进程架构：进程模型与职责、IPC 契约全貌、以「项目」为中心的数据流、关键业务链路时序、安全边界与错误约定。

---

## 1. 进程模型

```
┌─────────────────────────────── Electron 应用 ───────────────────────────────┐
│                                                                             │
│  主进程 (src/main)                        渲染进程 (src/renderer)            │
│  ├─ index.ts   入口装配器                  ├─ index.html  宿主 + CSP         │
│  ├─ 业务域模块 register(ctx)               ├─ App.vue     外壳/菜单/Toast     │
│  ├─ 文件系统 / spawn / 对话框              ├─ pages/*/    9 个页面组件        │
│  ├─ http(s) 请求（Qwen / 模型 / 模型下载 / 账号后端）├─ composables 全局状态/进度/提示  │
│  └─ 自定义协议 hgpreview:// p / tts         └─ assets/main.css 设计系统        │
│                    ▲                                    ▲                   │
│                    │        preload 桥接层              │                   │
│                    └──── src/preload/index.ts ──────────┘                   │
│                         contextBridge 14 命名空间 + 7 路进度通道               │
│                                                                             │
│  共享层 src/shared：ipc.ts / types.ts / errors.ts（错误文案映射）/ constants.ts │
│  独立脚本 src/agent：EOF 之外的实验 CLI，不进构建图、不打进包                  │
└─────────────────────────────────────────────────────────────────────────────┘
```

| 层 | 位置 | 职责 | 构建产物 |
|---|---|---|---|
| 主进程 | `src/main/` | 窗口与生命周期、运行环境（**分包**：ffmpeg / hyperframes / vidrender 各成一个 7z，首次用到时下载并解到 `userData/runtime/<包名>/`；其中 **vidrender 仅联调 demo 显式下载、不进产品默认缺包提示**，whisper 随安装包）的探测与解包、历史数据目录的归属证明与用户确认式处置（`legacy:*` 只给契约，界面在渲染层）、文件与目录读写、`spawn` 外部程序（whisper-cli / ffmpeg / HyperFrames / 7za）、全部网络请求（含**账号后端**）、对话框、自定义协议 | `out/main/index.js`（CJS） |
| 桥接层 | `src/preload/` | 用 `contextBridge` 暴露受控 API；进度通道按「7 路」转发（其中 `project:html-progress` 是**一条频道 + 按任务 id 分发**、订阅函数返回退订函数，其余为单槽回调）；`index.d.ts` 提供渲染层类型 | `out/preload/index.js`（CJS） |
| 渲染层 | `src/renderer/` | Vue 3 SFC 界面：外壳、菜单、9 个页面、全局设计系统；不直接触碰 Node/文件系统 | `out/renderer/`（`index.html` + `assets/*`） |
| 共享层 | `src/shared/` | IPC 频道名常量、跨进程载荷类型、**错误文案映射（`errors.ts`：原始报错 → 人话 + 配置分类）**，以及品牌等应用级公共常量（`constants.ts`）（编译期内联，无运行时产物） | 无（被打包进三端） |
| 实验脚本 | `src/agent/` | 独立 Tool Use Agent CLI，`node --experimental-strip-types` 直接运行 | 无（不进构建图） |

**进程数量**：全程单窗口（`mainWindow`）。窗口使用 `titleBarStyle: 'hidden'` 自绘标题栏，通过 `window:minimize` / `window:toggle-maximize` / `window:close` 三个 IPC 与主进程交互，最大化状态经 `window:maximized-change` 回推。

## 2. 启动时序

```
① 模块求值期（app ready 之前）
   ├─ USER_DATA_DIR = app.getPath('userData')   # 位置保持 Electron 默认（%APPDATA%\<package.json 的 name>），
   │                                      #   刻意不做 app.setPath，不做任何位置钉死
   ├─ writeIdentity(USER_DATA_DIR)        # 在当前 userData 落/更新归属标记 .shadowmill-data
   │                                      #   （{ appId: 'com.shadowmill.app', appName, dirName, at }；appId/dirName
   │                                      #    未变则跳过，幂等）——用于「归属证明」与将来改名后识别出这个目录
   ├─ mergeTree / pruneEmptyDirs / migrateFrom / findLegacyData / legacyInfo / resolveLegacy 定义
   │                                      #   legacyScanned / legacyFound：扫描结论缓存一次（MIGRATE_USER_DATA=0 时整段关闭）
   ├─ protocol.registerSchemesAsPrivileged([{ scheme: 'hgpreview', standard/secure/supportFetchAPI/stream }])
   │                                      #   紧随其后声明 USER_PREVIEW_DIRS = ['tts-output','voice','cast-preview']
   │                                      #   （语音产物路由 ?tts=1 / ?user=1 允许读的 userData 子目录白名单）
   └─ bootLog('main module loaded')      # 启动时序打点，写 userData/startup.log（下同）；STARTUP_LOG 在此解析一次并缓存
② app.whenReady()
   ├─ bootLog('app ready')
   ├─ protocol.handle('hgpreview', …)   # 预览文件协议；路由解析走 resolveHgPreviewPath(rawUrl)——判定按「段 + 查询标记」、不看 host：
   │                                    #   searchParams.get('tts') === '1'（现用写法）或 pathname 首段 === 'tts'（旧写法，兼容）
   │                                    #   ⇒ userData 下只读白名单；否则当项目名（pathname 首段）⇒ projects.projectDir()。两条都做目录穿越校验；
   │                                    #   → rangeResponse()（MIME 表 + Range 分片 206/416）→ 文件流返回；
   │                                    #   403（带 why）/ 404 / 500 写 userData/preview-protocol.log
   ├─ createWindow()                    # Menu.setApplicationMenu(null)、1200×800、hidden 标题栏、
   │                                    # backgroundColor '#0B1220'（与启动画面同色，首帧前不闪白）
   │                                    # contextIsolation:true / nodeIntegration:false / preload 指向 out/preload/index.js
   │                                    # dev 走 ELECTRON_RENDERER_URL，prod 走 loadFile('../renderer/index.html')
   │                                    # 另打点：window created → page load start → dom ready → page load finished → first paint
   ├─ ipcMain.handle('legacy:status', () => legacyInfo())          # 旧数据处置：主进程只回答「有没有 / 是什么」
   ├─ ipcMain.handle('legacy:resolve', (_e, action) => resolveLegacy(action))
   │                                    #   执行 迁移 / 删除 / 稍后（非法或缺省一律当 later）；界面由渲染层弹应用内弹窗
   │                                    #   —— 没有任何启动延迟，也不用原生 dialog.showMessageBox
   └─ 依次注册：settings → **account** → projects → **agent** → voice（`register` + `registerAlign`）→ video → whisper → updater → runtime
                                        # 前 9 个走 register(ctx)（ctx = { getWindow }，使各域对话框以主窗口为父）；
                                        # **account.register(ctx) 是新增的第 13 组频道**（5 条 account:*，不弹对话框、不依赖窗口），
                                        #   排在 settings 之后只表达「账号是最早可用的外围能力」，它不会 gate 任何本机功能；
                                        # **agent.registerScript(projects.projectDir) 是唯一带一个「非 ctx」参数的 register**：
                                        #   它把「项目名 → 项目目录」的解析函数注入给 agent（对话记录要用它拼 chat/index.json 与 chat/versions/ 的路径），
                                        #   只挂 script:generate / load-chat / append-round / read-version / set-active-version / clear-chat
                                        #   + 用 event.sender 推 script:progress；
                                        #   传函数而不是让 agent import projects —— 否则与 projects → agent 成环
                                        # updater 注册后 3s 做一次启动静默检查
                                        # runtime 最后注册，**启动只探测、不下载**（缺包时推「运行环境需要下载（体积）」；排最后只保证 handler 先挂上；缺包口径为 `PRODUCT_PACKS` = ffmpeg + hyperframes，不含 demo 用的 vidrender）
                                        # 各域 register 只挂 IPC 与订阅；重模块（electron-updater / openai）懒加载
③ 渲染层
   ├─ index.html 的启动画面先上屏（纯 HTML/CSS，不等 JS）——填掉「窗口已出现、Vue 未挂载」的空背景
   └─ main.ts createApp(App).mount('#app')
      ├─ 挂载后：#boot-splash 加 .boot-done 淡出，300ms 后移除
      └─ App.vue onMounted
         ├─ window.windowControls.onMaximizedChange(...)   # 标题栏图标态
         ├─ initRenderProgress()                           # 订阅 video:progress
         ├─ initRuntime()                                  # 订阅 runtime:progress + 查一次 runtime:status（外壳横幅）
         ├─ initEnvGate()                                  # 不重复订阅：watch useRuntime 的状态（全渲染层只有 useRuntime.ts 注册 onProgress）+ 驱动「下载运行环境」确认框
         ├─ initLegacyData()                               # 问一次 legacy:status → 有旧数据就弹应用内弹窗
         │                                                 #   （此刻首屏已渲染完，故主进程侧无需任何延迟）
         ├─ void restore()                                 # 账号（可选登录）：未登录直接返回；已登录时异步问一次 account:me，
         │                                                 #   不阻塞首屏；断网 / 5xx 保留上次展示态，只有 UNAUTHORIZED 才清
         └─ initApp()：
              localStorage['myapp.projectCtx'] 恢复当前项目
              → refreshProject()（project:list + project:load）
              → 首页已是初始页，不再调 goPage('home')（避免重复拉项目数据 + 首页重挂）
```

> **配置类弹窗（`useConfigPrompt`）没有 init 步骤**：它是模块级 `ref` 单例 + 由页面按需 `open()` / `fromResult()` 触发（与 `useEnvGate` 需要 `initEnvGate()` 订阅进度不同），`App.vue` 只负责把它渲染成 `.hf-modal`。因此启动链路上没有新增订阅。

> **历史数据目录（品牌改名的善后）怎么处理**（2026-10 定稿，本轮改为「界面在渲染层」）：userData 位置**保持 Electron 默认**（`app.getPath('userData')` = `%APPDATA%\<package.json 的 name>`，现 `shadowmill`，**没有 `setPath`**）。改名后老用户会看到「项目全没了」——数据其实还在 `%APPDATA%\my-app` 里。现在的做法是**扫描 + 弹窗让用户自己决定，绝不静默迁移**：`findLegacyData()` 扫 `LEGACY_DIR_NAMES`（现 `['my-app']`），四道闸依次为「排除自身 → 目录存在 → **归属证明通过** → 白名单条目确有数据（空壳不打扰）」，扫描结论由 `legacyInfo()` 缓存一次并经 `legacy:status` 交给渲染层；用户在**应用内弹窗**（`LegacyDataDialog.vue`，沿用 `.hf-modal` 体系）里选「迁移过来 / 删除旧数据 / 稍后再说」，选择经 `legacy:resolve` 回传、由 `resolveLegacy()` 执行（删除前会再校验目标确为 `%APPDATA%` 下清单内目录）。**主进程不做任何界面展示**：不再用原生 `dialog.showMessageBox`（与 Cyber UI 设计系统不一致），也**删掉了原先建窗后 1.5s 的 `setTimeout`**（显示时机由渲染层掌握，不需要「等首屏」的魔法数字）。迁移只搬 `OWN_DATA_ENTRIES`、目标不存在时整条目 `renameSync`、否则递归合并且**文件不覆盖**（唯一例外是仍处「出厂状态」的 `settings.json`，覆盖前先备份成 `.before-migrate.bak`），返回 `{ moved, skipped, failed }` 且**只有 `failed === 0` 才清缓存**（有失败可重试）。
> **归属证明（`isOurs`）**：`my-app` 这种名字太通用，`%APPDATA%` 下可能有别的应用也叫这个，所以先证明「它是我们的」——① 目录里**任意一个点开头的标记文件（名字不限）**内容里的 `appId` 等于常量 `APP_ID`（`'com.shadowmill.app'`）；② 否则看结构特征 `<目录>\projects\<项目名>\project.json` 是否存在（照顾标记机制上线之前的历史目录）。两条都不满足就**不提示、不迁移**。读取**只按内容认、不猜文件名**（`hasOurIdentity()`），因此改过多少次名都不会漏；写入仍用固定名 `.shadowmill-data`。
> **⚠ 代价**：`LEGACY_DIR_NAMES` 是**手工清单**，没有任何自动发现——以后改 `package.json` 的 `name` **必须**把旧名字加进去。另：业务模块的 userData 路径一律惰性求值（`projects.projectsRoot()` / `whisper.modelsDir()` / `runtime.runtimeDir()` / `settings.settingsFile()`）属**零代价的纯保险**（防将来有人重新引入 `setPath` 之类的改动）。完整算法与四道闸见 [files/main/index.ts.md](./files/main/index.ts.md) §3.1。

> **首屏慢的排查入口**：`userData/startup.log` 每行带「距进程启动的毫秒数」，可区分时间花在主进程模块加载、建窗、还是页面加载（历史数据的迁移 / 删除 /「稍后再说」也写在同一文件的一行里）；渲染层的可见反馈由 `src/renderer/index.html` 的启动画面提供。详见 [files/main/index.ts.md](./files/main/index.ts.md) §3.3 / §5 与 [files/renderer/index.html.md](./files/renderer/index.html.md) §2.2。

## 3. IPC 契约

### 3.1 四种通信形态

| 形态 | 主进程侧 | preload 侧 | 用途 |
|---|---|---|---|
| 请求/响应 | `ipcMain.handle(channel, fn)` | `ipcRenderer.invoke(channel, payload)` | 绝大多数业务调用（返回 `IpcResult`；**账号域返回 `AccountResult`**） |
| 同步取值 | `ipcMain.on(channel, fn)` + `event.returnValue` | `ipcRenderer.sendSync(channel)` | 仅 `update:version`（首屏要立刻显示版本号） |
| 单向指令 | `ipcMain.on(channel, fn)` | `ipcRenderer.send(channel)` | 窗口控制、取消对齐 |
| 进度推送 | `win.webContents.send(channel, data)` | `ipcRenderer.on(channel, cb)` 经命名空间回调转发 | HTML 生成、**内容脚本生成**、whisper、配音对齐、视频渲染、应用更新、运行环境包（`legacy:*` 刻意没有推送：结论由渲染层主动拉取） |
| 状态回推 | 同上 | 同上 | 窗口最大化状态变化 |

> 页面资源（预览 iframe / **角色预览 iframe** / 素材缩略图 / 视频 / 音频）**不走 IPC**：它们走主进程注册的自定义协议 `hgpreview://`，见 §7「安全边界」。
>
> **账号是纯请求/响应**：5 条 `account:*` 都是 `invoke`，**没有任何推送**（登录 / 注册是一次请求-响应，没有阶段进度）；回执不是 `IpcResult`，而是 `AccountResult` / `AccountSendCodeResult`（`code` + `message`），见 §3.5。

| `updateTools` | 应用自更新：检查 / 下载 / 取消 / 重启安装 / **状态查询（`status`）** / **打开日志** / **查看更新日志（`changelog`）** + 进度订阅 | `src/main/updater/`（目录 4 文件，出口 `updater/index.ts`） |
| `runtimeTools` | 运行环境（分包 **ffmpeg / hyperframes / vidrender**，后者仅 demo 显式下载、不进产品默认缺包提示）：状态查询 / 主动准备（`prepare(packs?)`，省略 = 全部产品包；可显式 `prepare(['vidrender'])`）/ **取消（`cancel`）** / 进度订阅 | `src/main/runtime.ts` |
| `legacyTools` | 旧版本数据：状态查询（`status`）/ 回传选择（`resolve`）；**无推送订阅** | `src/main/index.ts` |

### 3.3 频道总表（源：`src/shared/ipc.ts`）

**Account（`src/main/account/`，本轮新增；账号 / 可选登录）**

| 频道 | preload | 说明 |
|---|---|---|
| `account:send-code` | `accountTools.sendCode(email)` | 发送注册验证码；成功回 `AccountSendCodeOk`（`expiresInSeconds` / `resendAfterSeconds`，**开发模式下多一个 `devCode`**，打包版由主进程剥掉），失败回 `AccountFail`（`code` + `message`） |

### 3.4 结果约定

- 业务类 `invoke` 统一返回 `{ ok: true, ...数据 }` 或 `{ ok: false, message, detail?, canceled? }`（`src/shared/types.ts` ① 节的 `IpcFail` / `IpcResult<T>`；`message` 为可选，取消分支只有 `canceled: true`）；取消类对话框以 `canceled: true` 表达，UI 侧不弹错误。
- **失败分支还有两组可选字段**：`needPacks?: RuntimePackName[]`（运行时缺包，`'ffmpeg'` / `'hyperframes'` / `'vidrender'`；产品代码只回前两者，vidrender 只在 demo 显式通路出现）与 `needConfig?: ConfigTarget`（`'model' | 'voice'`，**配置类**错误）+ `title?: string`（弹窗标题）。两者语义不同：`needPacks` **要续做**（用户在确认框里点「继续」后原参数重发），`needConfig` **不驱动流程**，只是把「这个错误该去哪修」交给界面分流。**余额 / 欠费刻意不给 `needConfig`**（去设置修不了余额），它走内嵌状态行。
- **账号域是独立的第三套结果类型**（`src/shared/types.ts` 的「账号」一节）：成功 `{ ok: true, session | expiresInSeconds/resendAfterSeconds }`、失败 `{ ok: false, code, message }`（`AccountFail`）。**没有 `detail` / `needPacks` / `needConfig`**——登录失败按 14 个 `AccountErrorCode` 分流（如 `CODE_COOLDOWN` 提示稍后再试），`message` 已由主进程翻成人话；`logout()` 直接返回 `void`。
- **`message` 与 `detail` 分两层**：`message` 是给终端用户的人话（发生了什么 + 能做什么），`detail` 是可选的排障信息（原始报错 / HTTP 状态 / 请求地址），由 UI 的「查看详情」折叠展示。目前主要落在 `update:*` 一族（`UpdateCheckResult.message` 为必填、`detail` 可选；`UpdateProgressPayload.detail` 仅 `error` 阶段非空；`update:changelog` 的失败分支同理），详见 [files/main/updater.md](./files/main/updater.md) §5 的文案对照表。
- **「英文原始报错 → 人话文案」的唯一映射表是 `src/shared/errors.ts`**（纯函数、无副作用、不 import electron）：`friendlyError(err, ctx)` 按固定顺序分十档判定（余额/欠费 → 未启用/未配置 → 鉴权 401/403 → 地址或模型不存在 404/405 → 限流（配额耗尽先于 429）→ 5xx → 内容合规 → 参数 400/422 → 网络 errno → 文件系统 errno → 兜底），产出 `message`（始终带 `label：` 前缀）、`detail`（原始报文首行截断 500 字符 + `extras`）、以及配置类的 `needConfig` / `title`。接入点是 `agent/html.ts`（经 `agent/chat.ts`）/ `settings.ts` / `voice/api.ts` / `projects/ipc/*`。**账号域刻意不走这张表**：它的 14 个错误码是后端业务码的镜像（要驱动界面分流），文案由 `src/main/account/api.ts` 的 `FALLBACK_MESSAGE` 兜底。详见 [files/shared/errors.ts.md](./files/shared/errors.ts.md) 与 `docs/error-mapping.md`。
- **配置类错误在渲染层的升级**：拿到 `res.needConfig` 后由 `useConfigPrompt`（模块级单例）弹 `.hf-modal`（**主按钮固定「去设置」**、次按钮「取消」），**刻意不显示「查看详情」**；`needConfig` 为假的失败仍按原样走内嵌状态行 / toast。设置页的「测试连接」刻意不弹。
- 少数查询类接口直接返回数组/对象（`project:list`、`project:load`、选择文件类返回 `string | null`）。
- 进度通道**两种分发方式**：`project:html-progress` 是**一条频道 + 按任务 id 分发**——preload 用模块级 `_progressCbs`（`Map<taskId, 回调>`）+ `_htmlProgressBound`，只绑一次 `ipcRenderer.on`，收到后按 `data.taskId` 分发，`onTaskProgress(taskId, cb)` 返回退订函数；**其余 5 路**（script / whisper / align / update / runtime）仍是单槽回调（模块级 `_xxxProgressCb` + `_xxxProgressBound`，重复注册只替换回调），`video:progress` 则直接 `ipcRenderer.on`。

### 3.5 账号 / 可选登录（本轮新增）

账号是**可选的外围能力**，不是准入门槛。三条不变量写死在 `src/shared/types.ts` 的账号契约与 `src/main/account/` 的文件头注释里：

| 不变量 | 含义 | 代码落点 |
|---|---|---|
| **① 未登录可用** | 账号不 gate 任何本机流水线；没有登录也能建项目、生成、转录、配音、转视频 | `useAuth.ts` 不 gate 任何页面；`account:me` 未登录直接回 `UNAUTHORIZED`（不抛错）；`account:logout` 未登录也安全（幂等） |
| **② 令牌不出主进程** | 渲染层从头到尾拿不到 token；HTTP 与令牌都在主进程 | `api.ts` 的 `IssuedSession` 只在本进程流转；`index.ts` 的 `remember()` 只回 `AccountSession`（`user` + `expiresAt`）；`store.ts` 用 `safeStorage` 加密写 `userData/account.bin`，**safeStorage 不可用时只存内存、不降级明文** |
| **③ 断网保留登录态** | 断网不等于未登录：只有服务端明确 `UNAUTHORIZED` 才清态，网络错误 / 5xx 保留上次展示 | `index.ts` 的 `currentSession()` 只在 `outcome.code === 'UNAUTHORIZED'` 时 `store.clear()`；`useAuth.restore()` 同样只在 `UNAUTHORIZED` 时清展示态 |

**为什么账号请求必须放主进程**（`src/main/account/api.ts` 头注释）：① 渲染层 CSP 是 `connect-src 'self'`，页面直连后端会被浏览器拦掉；② 打包后页面 Origin 是 `file://`，后端 CORS 只放行 `http://localhost:*`，直连也过不了预检；③ 令牌不该交给渲染层（XSS 拿不到它，也就偷不走会话）。

**五个频道 + 三条不变量之外的两点事实**：注册 / 登录成功即把令牌写进 `safeStorage` 并返回展示字段；后端签发的是**不透明会话令牌**（30 天滑动续期，客户端无 refresh、不解析 JWT，撤销走 `POST /api/auth/logout`）。后端在另一个仓库（`E:\my\demo`：会话表 `auth_sessions`、令牌形如 `sm_` + 43 字符、业务码 `code` 字段），**方案与后端实施记录见 [`docs/account-integration.md`](../docs/account-integration.md)**（§8 是实施记录）。

目录级实现说明见 [files/main/account.md](./files/main/account.md)；渲染层半边（登录态镜像 / 弹窗 / 纯校验）见 [04-目录架构-src-renderer.md](./04-目录架构-src-renderer.md) 与 [common.md](./files/renderer/src/common.md)、[components.md](./files/renderer/src/components.md)。

- 每个页面/组件通过 `useAppStore` 的 `appState.project` 读取当前项目；任何写操作落盘后调用 `refreshProject()` 重新拉取，`hasContent / hasAudio / hasSubtitle / hasHtml / hasVideo` 五个 computed 驱动 `StepBar` 的点亮状态。
- 当前项目上下文持久化在渲染层 `localStorage['myapp.projectCtx']`（只存 `{ name }`），prod 下 `file://` 同源，重启后自动延续。
- **项目只有一种形态**：`userData/projects/<项目名>/` 下用户自建、可读可写的普通项目；`hasContent` / `hasAudio` / `hasSubtitle` / `hasHtml` / `hasVideo` 五个 computed 一律只看当前项目自身的产物字段（`hasHtml` 额外要求 `htmlExists && htmlPath` 同时成立）。
- **`userData` 本身的绝对位置**：`%APPDATA%\<package.json 的 name>`（现 `%APPDATA%\shadowmill`，Electron 默认语义，`index.ts` 不做 `setPath`），因此上面的相对路径在**同一次改名之间**保持稳定；改名导致目录变化时，由启动时的「归属证明 + 用户确认式迁移」把老目录内容搬过来（用户点「迁移过来」才搬）。
- **HTML 产物现在有两种形态**：`project:generate-html` 先做一次**结构规划**再分支——判 `single` 产出单文件 `index.html`；判 `chapters` 走章节模式（每章一个 `pages/cNN.js`，`index.html` 由主进程 `chapters.ts` 的 `buildSkeleton` 按章节清单确定性生成，章时间从 0 开始、整片偏移由应用累加，章节清单落 `Project.chapters`）。两种形态都由既有频道承载（`project:generate-html` / `project:modify-html` / `project:download-html`），**IPC 频道数不变**。
  - **角色只有全局一份**：真源是 `<userData>/cast-library/`（`index.json` 元数据 + `<id>.js` 绘制代码），**与项目无关**——没有当前项目也能建 / 改 / 删 / 预览。项目里只记「本片用了哪几个」（`Project.cast` 解析后是 `ProjectCastMember[]`，`project.json` 里只落 `[{ id, selected }]`，元数据读项目时按 id 从库补全）。生成 / 改稿 / 预览 / 渲染前由主进程把勾中的从库**复制**成 `<项目>/cast/` 副本（`syncProjectCast`）。**注入**：章节模式骨架按传入的 `cast` 列表写 `<script src="./cast/<id>.js">`（「传谁引谁」），单文件模式由 `cast.injectCastTags()` 整组插在模型第一个 `<script>` 之前。**勾选变化立即生效**：`project:save-cast` 落盘后先同步副本、再 `refreshCastInPage()`。
  - **角色层（分层约定）**：角色**永远画在自己那张透明画布上**，叠在背景之上；每帧先清层再画，**禁止在角色层填整屏底色**。工具是 `core.js` v2 的两个助手 `MC.castLayer(stage, 宽, 高)` / `MC.clearLayer(ctx)`。层由**章节自己建**（骨架只负责把角色脚本排在章节之前）。
  - **`core.js` 按版本同步进项目**：骨架固定引 `<script src="./core.js">`（全局对象 `MC`），真源 `vendor/shadowmill/core.js`（`CORE_VERSION = '7'`），项目里那份是副本（`core.js` + `.core-version`），由 `coreLib.syncCoreTo()` **按 `CORE_VERSION` 覆盖**。同步时机五处：**写骨架前 / 单文件注入前（仅当勾了角色）/ 预览前（仅当页面引了它）/ 导出前 / 渲染前**。导出单文件时它被**内联**（`coreLib.readProjectCore`）。
  - **p5 一律实例模式 + WEBGL**：`p5.brush` 2.2.3 强制 WEBGL；绘制写在 `p.draw()` 里，每帧 `window.__brushT = t; inst.redraw()`。两条硬约束：**WEBGL 的原点在画布中心**（`p.draw()` 里 `p.clear()` 之后必须 `p.translate(-W/2, -H/2)`）、**p5.brush 只认 11 种笔型**（`ink` 不是笔型）。
  - **全局角色库 = 唯一真源**：库在 `<userData>/cast-library/`（用户资产，可备份、可迁移、不进安装包）。项目里的 `cast/<id>.js` 只是**产物副本**——`hgpreview://` 只放行项目目录、渲染静态服务器 root 只有「编译产物目录 + 项目目录」，所以生成前由主进程 `syncProjectCast` 把勾中的那份**复制**进项目目录；**副本归应用维护，不归项目管**。角色相关的频道本轮整体搬进 `Cast` 组 6 条 + 动作 5 条 + `Project` 组的 `project:save-cast`；preload 侧是 `castTools`。
  - **角色能看见长相**：主进程 `cast:preview` 把内置 `core.js` + 库里这份角色代码**内联**成一页自包含 HTML，落到 `<userData>/cast-preview/<id>.html`，渲染层用 `hgpreview://…?user=1` 载进 `iframe`（`components/CastShot.vue`）。界面上四处：「角色」页卡片墙 /「角色」页「修改角色」弹窗大图 /「HTML生成」页 ·「角色」区的卡片缩略图 /「内容脚本」页选角色弹窗的方格。**边界**：静态一帧；水彩角色只画得出 Canvas 2D 部分。
  - **改稿是「路由 → 定向编辑」两段**：`project:modify-html` 在章节模式下先只发「大纲 + 角色表 + 用户的话」让模型报要改哪几份文件，再只读那几份源码定向编辑；**路由失败自动回退成「发全部源码」**。**没有新增 IPC 频道**。
  - **改稿不碰角色**：单文件模式的 `project:modify-html` 只把**只读角色表**发给模型，`cast.stripCastFileBlocks()` 只作兜底剥块；章节模式 `applyChapterEdit` 的路径白名单只剩 `pages/cNN.js`。角色的新建 / 修改都在「角色」页。
- **项目素材库（图片 / 视频）的链路**：添加素材（`project:pick-media` → `project:add-materials` 复制进 `images/` / `video/` 并登记）→ 卡片墙上勾选（`selected`，经 `project:save-materials` 整份回写）→ 生成 / 修改时提交 `materialIds` → 主进程按 id 过滤、拼「【图片素材】/【视频素材】」提示词 → 模型在 HTML 里写项目内相对路径。**上限与白名单只有一处**（`src/shared/constants.ts`）；**移除 ≠ 删除**（只摘登记、文件保留）。
- **「路径 → URL」收口到一处**：渲染层一律走 `src/renderer/src/utils/url.ts` 的 `previewUrl()`（项目内资源）与 `userPathUrl()` / `userFileUrl()`（项目外产物），两者都**逐段 `encodeURIComponent`**，与主进程 hgpreview 处理器「按段 decode」的口径对应。

### 5.4 字幕配音对齐（双模式）

- **模式 A（音频驱动）**：逐句 TTS 实测时长 → 重排字幕时间轴（音频不变速）。
- **模式 B（时间轴驱动）**：以字幕时间戳为槽位摆放配音，溢出时 `atempo` 加速（上限 `1.15`），仍放不下则顺延后续句子。
- 两者共用：逐句合成 → 24k 单声道 WAV → `ffprobe` 量时长；`buildTrack` 用静音补齐 + `concat -c copy` 零重编码装配整轨；进度经 `voice:align-progress` 回推，可经 `voice:align-cancel` 取消。
- 产物落 `userData/voice/align-<时间戳>/`（**项目外**），试听源由渲染层 `userPathUrl()` 换算成 `hgpreview://user/…?user=1`。
- 失败分支：`AlignSection` 先判 `useConfigPrompt().fromResult(fail)`（配置类优先），再判 `needPacks`（缺 ffmpeg 弹环境确认框），都不是才 toast。

      │          │         │        │          │

      │          │         │        │          ▲

      │          │         │        │          ▲
      │          │         │        │      voice/ttsAlign（ffmpeg/ffprobe 走 hfEnv）
      │          │         │        │
      │          │         │        └─ agent/script ──→ 拼提示词 / 调模型 / 解析 JSON + 七个 script:* 频道
      │          │         │                  └─ agent/chatLog ──→ 只读写 <项目目录>/chat/
      │          │         └─ whisper（CLI 定位 + ffmpeg 预转 + 从 voice/vad.ts 取 VAD）

  account/ 是**独立的一条边**：index.ts ──→ account（只注册 5 条 account:*；account 只 import shared 与 electron/node:*）
  agent/index.ts 只把 agent/chat · agent/html · agent/script 的具名导出原样挂出（依赖单向 chat ← html / script）
  chapters（projects/ 在章节模式下调它做解析 / 校验 / pages 读写 / 骨架；chapters 不 import projects/）
  cast/（table / inject / preview / library / presets / actions / demo；projects/ 调它，cast 不 import projects/）
  editRoute（改稿路由：projects/chaptersFlow.ts 的 applyChapterEdit 调它；不 import 任何主进程模块）
  coreLib（core.js 版本同步：projects/ 与 video.ts 调它；不 import electron）
  index.ts 装配期另调 settings.isPristineSettings()（迁移老数据时判定新 settings.json 是否仍是出厂状态）

## 7. 安全边界

| 面 | 措施 | 位置 |
|---|---|---|
| 进程隔离 | `contextIsolation: true`、`nodeIntegration: false`，渲染层只能经 preload 白名单 API 访问系统能力 | `src/main/index.ts` |
| 本地文件预览 | 自定义 `hgpreview://` 协议（`standard` + `secure` + `supportFetchAPI` + `stream`），路径解析由独立函数 **`resolveHgPreviewPath(rawUrl)`** 承担（返回 `{ full, why }` 或 `null`），**两条分支**：`hgpreview://p/<项目名>/<相对路径>` 仅允许读目标项目目录内的文件；`hgpreview://user/<相对路径>?user=1` 仅允许读 userData 下 `USER_PREVIEW_DIRS = ['tts-output','voice','cast-preview']` 白名单目录内的文件——**不在白名单即 403**（`why = not-in-whitelist:<top>`）、穿越即 403（`why = traversal`），两条分支都做目录穿越校验；403 / 404 / 500 一律写 `preview-protocol.log`。MIME 由 `previewMime` 按扩展名显式给出；响应统一由 `rangeResponse()` 构造，**支持 `Range` 字节范围取**（`206` + `Content-Range` / 非法范围 `416`）。**页面消费方五类**：HTML 预览 iframe、**角色预览 iframe（`CastShot.vue`）**、素材缩略图、视频预览 `<video>`、**音频试听 `<audio>`**；URL 一律由 `src/renderer/src/utils/url.ts` 的 `previewUrl()` / `userPathUrl()` / `userFileUrl()` 拼装（**逐段 `encodeURIComponent`**），渲染层不再出现 `file://` 拼接 | `src/main/index.ts`、`src/renderer/src/utils/url.ts` |
| iframe | 预览 iframe 使用 `sandbox="allow-scripts allow-same-origin"`；角色预览 iframe 另加 `pointer-events: none`、地址带 `&e=<epoch>`（`userFileUrl` 已带 `?user=1`，续接必须用 `&`） | `src/renderer/src/pages/HtmlGenPage/`、`src/renderer/src/components/CastShot.vue` |
| CSP | `index.html` meta：`default-src 'self'`，仅放行 `file:` / `hgpreview:` 的 frame 与媒体、`'unsafe-inline'` 样式，脚本禁 `unsafe-eval`（SFC 预编译）；dev 由 `cspDevWsPlugin` 追加实际 `ws://` 源。**`connect-src 'self'` 就是账号 HTTP 必须放主进程的原因之一**（页面直连后端会被 CSP 拦掉） | `src/renderer/index.html`、`electron.vite.config.ts` |
| 注入 | 字幕等文本一律 `textContent` / `escTxt()` 写入，不拼 `innerHTML` | `src/renderer/src/utils/escape.ts` 及各页面 |
| 路径逃逸 | 项目内所有路径由 `projectDir()` 派生并做前缀校验；协议处理与 Agent 脚本各有独立的 `safePath` 校验 | `src/main/index.ts`、`src/main/projects/ipc/project.ts`、`src/agent/index.ts` |
| 数据目录归属 | userData 位置保持 Electron 默认；迁移前先做**归属证明**，不通过就**不提示、不迁移**；迁移只搬白名单条目且**文件不覆盖**，删除前二次校验 | `src/main/index.ts`、`src/main/settings.ts` |
| 密钥 | API Key 仅存本机 `userData/settings.json`，不外传；渲染层只读不落盘 | `src/main/settings.ts`、`src/main/voice/` |
| **账号令牌** | **令牌只存主进程**：`safeStorage.encryptString` 加密写 `userData/account.bin`（Windows = DPAPI / macOS = 钥匙串），**不写明文**；safeStorage 不可用时**只存内存**、绝不降级明文；IPC 只回 `AccountSession`（展示字段 + 过期时间），渲染层拿不到 token。**未登录不影响任何本机能力** | `src/main/account/store.ts`、`src/main/account/index.ts` |
| 错误文案 | 原始英文报文**不进用户文案**：`friendlyError()` 只把「人话 + 可做什么」放进 `message`，状态码 / 厂商 code / 请求地址一律只进 `detail`（配置类弹窗连 `detail` 都不显示）。账号域同理：`AccountFail.message` 只放人话，`code` 驱动界面分流 | `src/shared/errors.ts`、`src/main/account/api.ts` |
| 外部程序 | 只调用「安装包内的 `resources/whisper`（whisper-cli）、`resources/tools`（7za）与 `resources/bin`（小内核 `vidrender-encode.exe`，仅 demo）」和「运行环境包解出的 `<userData>/runtime/<包名>/`（ffmpeg / HyperFrames / vidrender）」；`spawn` 参数为数组形式不经 shell | `src/main/{hfEnv,video,whisper,ttsAlign}.ts` |
| 更新源 | 更新源地址可选；安装包经 electron-updater 校验 `sha512` 后才允许安装；失败文案分两层，原始报错落 `userData/updater.log` 并可经 `update:open-log` 一键定位 | `src/main/updater/`、`src/main/settings.ts` |

> **为什么以前 `'file:///' + encodeURI(path)` 能用**：旧版 dev 与生产都是 `file://` 源，所以渲染层直接拼 `file://` 读本地音频 / 视频成立。`9615eaf`（electron-vite 重构）让 dev 渲染页变成 `http://localhost` 源之后，Chromium 拒绝 http 页读 `file://`，音频试听在 dev 下静默失效。这就是「路径 → URL 收口 + 音频预览改走 `hgpreview://`」的由来（CHANGELOG #25 / #26 / #27）。**唯一保留的 `file:///`** 在主进程 `src/main/video.ts`：它喂给 Chromium `--dump-dom` 量 GSAP 时间轴，**不在页面里、不受同源策略约束**。
