# 01 · 架构总览

> 本文件描述应用的跨进程架构：进程模型与职责、IPC 契约全貌、以「项目」为中心的数据流、关键业务链路时序、安全边界与错误约定。

---

## 1. 进程模型

```
┌─────────────────────────────── Electron 应用 ───────────────────────────────┐
│                                                                             │
│  主进程 (src/main)                        渲染进程 (src/renderer)            │
│  ├─ index.ts   入口装配器                  ├─ index.html  宿主 + CSP         │
│  ├─ 业务域模块 register(ctx)               ├─ App.vue     外壳/菜单/Toast     │
│  ├─ 文件系统 / spawn / 对话框              ├─ pages/*/    9 个页面组件        │
│  ├─ http(s) 请求（Qwen / 模型 / 模型下载）  ├─ composables 全局状态/进度/提示  │
│  └─ 自定义协议 hgpreview://               └─ assets/main.css 设计系统        │
│                    ▲                                    ▲                   │
│                    │        preload 桥接层              │                   │
│                    └──── src/preload/index.ts ──────────┘                   │
│                         contextBridge 9 命名空间 + 5 进度通道                │
│                                                                             │
│  共享层 src/shared：ipc.ts / types.ts / constants.ts（公共常量）            │
│  独立脚本 src/agent：EOF 之外的实验 CLI，不进构建图、不打进包                  │
└─────────────────────────────────────────────────────────────────────────────┘
```

| 层 | 位置 | 职责 | 构建产物 |
|---|---|---|---|
| 主进程 | `src/main/` | 窗口与生命周期、文件与目录读写、`spawn` 外部程序（whisper-cli / ffmpeg / HyperFrames）、全部网络请求、对话框、自定义协议 | `out/main/index.js`（CJS） |
| 桥接层 | `src/preload/` | 用 `contextBridge` 暴露受控 API；进度通道单订阅；`index.d.ts` 提供渲染层类型 | `out/preload/index.js`（CJS） |
| 渲染层 | `src/renderer/` | Vue 3 SFC 界面：外壳、菜单、9 个页面、全局设计系统；不直接触碰 Node/文件系统 | `out/renderer/`（`index.html` + `assets/*`） |
| 共享层 | `src/shared/` | IPC 频道名常量、跨进程载荷类型，以及品牌等应用级公共常量（`constants.ts`）（编译期内联，无运行时产物） | 无（被打包进三端） |
| 实验脚本 | `src/agent/` | 独立 Tool Use Agent CLI，`node --experimental-strip-types` 直接运行 | 无（不进构建图） |

**进程数量**：全程单窗口（`mainWindow`）。窗口使用 `titleBarStyle: 'hidden'` 自绘标题栏，通过 `window:minimize` / `window:toggle-maximize` / `window:close` 三个 IPC 与主进程交互，最大化状态经 `window:maximized-change` 回推。

## 2. 启动时序

```
① 模块求值期（app ready 之前）
   ├─ migrateLegacyUserData()            # 最先执行：改名兼容，userData 由 %APPDATA%\my-app 搬到 %APPDATA%\shadowmill
   │                                     # （打点路径 STARTUP_LOG 在其后才解析，避免提前建出新目录让迁移误判）
   ├─ protocol.registerSchemesAsPrivileged([{ scheme: 'hgpreview', standard/secure/supportFetchAPI/stream }])
   └─ bootLog('main module loaded')      # 启动时序打点，写 userData/startup.log（下同）
② app.whenReady()
   ├─ bootLog('app ready')
   ├─ protocol.handle('hgpreview', …)   # 预览文件协议：目录穿越校验 → 读字节 → 按 MIME 表返回
   ├─ createWindow()                    # Menu.setApplicationMenu(null)、1200×800、hidden 标题栏、
   │                                    # backgroundColor '#0B1220'（与启动画面同色，首帧前不闪白）
   │                                    # contextIsolation:true / nodeIntegration:false / preload 指向 out/preload/index.js
   │                                    # dev 走 ELECTRON_RENDERER_URL，prod 走 loadFile('../renderer/index.html')
   │                                    # 另打点：window created → page load start → dom ready → page load finished → first paint
   └─ 依次 register(ctx)：settings → projects → voice → ttsAlign → video → whisper → updater
                                        # ctx = { getWindow }，使各域对话框以主窗口为父
                                        # updater 最后注册，并在 3s 后做一次启动静默检查
                                        # 各域 register 只挂 IPC 与订阅；重模块（electron-updater / openai）懒加载
③ 渲染层
   ├─ index.html 的启动画面先上屏（纯 HTML/CSS，不等 JS）——填掉「窗口已出现、Vue 未挂载」的空背景
   └─ main.ts createApp(App).mount('#app')
      ├─ 挂载后：#boot-splash 加 .boot-done 淡出，300ms 后移除
      └─ App.vue onMounted
         ├─ window.windowControls.onMaximizedChange(...)   # 标题栏图标态
         ├─ initRenderProgress()                           # 订阅 video:progress
         └─ initApp()：
              localStorage['myapp.projectCtx'] 恢复当前项目
              → refreshProject()（project:list + project:load）
              → 首页已是初始页，不再调 goPage('home')（避免重复拉项目数据 + 首页重挂）
```

> **首屏慢的排查入口**：`userData/startup.log` 每行带「距进程启动的毫秒数」，可区分时间花在主进程模块加载、建窗、还是页面加载；渲染层的可见反馈由 `src/renderer/index.html` 的启动画面提供。详见 [files/main/index.ts.md](./files/main/index.ts.md) §3.3 / §5 与 [files/renderer/index.html.md](./files/renderer/index.html.md) §2.2。

## 3. IPC 契约

### 3.1 四种通信形态

| 形态 | 主进程侧 | preload 侧 | 用途 |
|---|---|---|---|
| 请求/响应 | `ipcMain.handle(channel, fn)` | `ipcRenderer.invoke(channel, payload)` | 绝大多数业务调用（返回 `IpcResult`） |
| 同步取值 | `ipcMain.on(channel, fn)` + `event.returnValue` | `ipcRenderer.sendSync(channel)` | 仅 `update:version`（首屏要立刻显示版本号） |
| 单向指令 | `ipcMain.on(channel, fn)` | `ipcRenderer.send(channel)` | 窗口控制、取消对齐 |
| 进度推送 | `win.webContents.send(channel, data)` | `ipcRenderer.on(channel, cb)` 经命名空间回调转发 | HTML 生成、whisper、配音对齐、视频渲染、应用更新 |
| 状态回推 | 同上 | 同上 | 窗口最大化状态变化 |

### 3.2 preload 的 9 个命名空间

| 命名空间 | 覆盖域 | 对应主进程模块 |
|---|---|---|
| `electronAPI` | `platform`、`versions`（node/chrome/electron） | 无（纯数据） |
| `appTools` | 剪贴板复制 | `src/main/index.ts` |
| `windowControls` | 最小化 / 最大化切换 / 关闭 / 最大化状态订阅 | `src/main/index.ts` |
| `hfTools` | HTML 预览与 HyperFrames 转视频 | `src/main/video.ts` |
| `settingsTools` | 自定义模型设置与连接测试、渲染档位、更新设置 | `src/main/settings.ts` |
| `voiceTools` | 音色管理、文字生音频、字幕配音对齐 | `src/main/voice.ts` / `ttsAlign.ts` |
| `whisperTools` | whisper.cpp 转录与模型管理 | `src/main/whisper.ts` |
| `projectTools` | 项目化流水线（字幕 / 内容脚本 / HTML / 视频 / 音频） | `src/main/projects.ts` |
| `updateTools` | 应用自更新：检查 / 下载 / 取消 / 重启安装 / **打开日志** + 进度订阅 | `src/main/updater.ts` |

### 3.4 结果约定

- 业务类 `invoke` 统一返回 `{ ok: true, ...数据 }` 或 `{ ok: false, message, detail?, canceled? }`（`src/shared/types.ts` ① 节的 `IpcFail` / `IpcResult<T>`；`message` 为可选，取消分支只有 `canceled: true`）；取消类对话框以 `canceled: true` 表达，UI 侧不弹错误。
- **`message` 与 `detail` 分两层**：`message` 是给终端用户的人话（发生了什么 + 能做什么），`detail` 是可选的排障信息（原始报错 / HTTP 状态 / 请求地址），由 UI 的「查看详情」折叠展示。目前主要落在 `update:*` 一族（`UpdateCheckResult.message` 为必填、`detail` 可选；`UpdateProgressPayload.detail` 仅 `error` 阶段非空），详见 [files/main/updater.ts.md](./files/main/updater.ts.md) §5 的文案对照表。
- 少数查询类接口直接返回数组/对象（`project:list`、`project:load`、选择文件类返回 `string | null`）。
- 进度通道为**单订阅**语义：preload 用模块级 `_xxxProgressCb` + `_xxxProgressBound` 标志，重复注册只替换回调，避免页面切换叠加监听。

## 4. 以「项目」为中心的数据流

```
                    ┌───────────────────────────────────────────┐
                    │  userData/projects/<项目名>/project.json   │
                    │  { title, subtitle, content,              │
                    │    render, audioFile, htmlPath,           │
                    │    videoPath, videoMaterial }             │
                    └───────────────────────────────────────────┘
                          ▲            ▲             ▲
   渲染层全局状态           │            │             │
   useAppStore.appState     │            │             │
   （currentName/project/   │            │             │
     myProjects）           │            │             │
        │                   │            │             │
        ├─ ① 音色管理 ───────┼────────────┼─────────────┼─→ settings.json（voiceProfiles 本地映射）
        │                   │            │             │     千问云端（克隆音色）
        ├─ ② 文字生音频 ─────┼────────────┼─→ audio/ ───┘     （audioFile 写入 project.json）
        │                   │            │
        ├─ ③ 文字转字幕 ─────┼─→ subtitle.txt                （手写 / 脚本旁白 / whisper 转录）
        │                   │            │
        ├─ ④ 字幕生成 HTML ──┼────────────┴─→ index.html       （含主进程注入的 <audio id="myv-bgm"> 音轨；+ index.preview.html 预览副本）
        │                   │
        └─ ⑤ 视频预览 ───────┴──────────────→ *.mp4           （转视频入口在 ④ 页；videoPath 回写 project.json）
```

- 每个页面/组件通过 `useAppStore` 的 `appState.project` 读取当前项目；任何写操作落盘后调用 `refreshProject()` 重新拉取，`hasContent / hasAudio / hasSubtitle / hasHtml / hasVideo` 五个 computed 驱动 `StepBar` 的点亮状态。
- 当前项目上下文持久化在渲染层 `localStorage['myapp.projectCtx']`（只存 `{ name }`），prod 下 `file://` 同源，重启后自动延续。
- **项目只有一种形态**：`userData/projects/<项目名>/` 下用户自建、可读可写的普通项目；`hasContent` / `hasAudio` / `hasSubtitle` / `hasHtml` / `hasVideo` 五个 computed 一律只看当前项目自身的产物字段（`hasHtml` 额外要求 `htmlExists && htmlPath` 同时成立）。

## 5. 关键业务链路

### 5.1 HTML 生成（最复杂的一条链路）

> 两个频道都不要写混：**界面上是两个并列的按钮**——「生成 HTML」走 `project:generate-html`（提示词**不含**现有页面），「按需求修改」走 `project:modify-html`（提示词把当前 `index.html` 全文置于最前）；没有 HTML 时「按需求修改」按钮禁用。**「生成 HTML」点一次即执行、没有二次确认**（已有 HTML 时直接覆盖，按钮文案恒为「生成 HTML」），走的仍是 generate、忽略现有页面。两个 handler 各自独立、**没有合并**，下面以 generate 为例画链路，modify 除提示词多一段现有源码外其余步骤一致（见 [files/main/projects.ts.md](./files/main/projects.ts.md) §5.2 / §5.3）。

```
HtmlGenPage/index.vue（提示词 + 「项目素材」里字幕/视频素材的选择：视频全页只有这一个下拉，可选项目现有素材或当场导入自定义文件；背景音频在「预览」卡片里选定。生成侧是**两个并列按钮**：「生成 HTML」→ generate、「按需求修改」→ modify，区别由**每个动作按钮内部各带一个的 `?`** 悬浮说明承载（一个动作一个、只讲自己那个动作，动作行末尾不再有独立 `?`）；「按需求修改」在无 HTML 时禁用，「生成 HTML」点一次即执行、无二次确认）
   │  projectTools.generateHtml(name, prompt, { subtitleProject, videoPath })
   │  （「按需求修改」改走 projectTools.modifyHtml(name, prompt, materials) → project:modify-html）
   ▼
projects.ts  register → project:generate-html（或 project:modify-html）
   ├─ resolveMaterials(proj, payload)：解析字幕来源（当前项目 / 其他项目）与视频「要不要带上」（`''` = 不带 / `'__current__'` = 当前项目视频素材，**不带路径**；视频的自定义导入走 project:set-video）
   ├─ buildMaterialPrompt() + buildContentBlock()：拼接内容脚本（style + 场景 narration/visual/durHint）
   ├─ htmlAgent.chatWithCustomModel({ prompt, system, onProgress })   ← 流式
   │     ├─ 内部读 settings.getCustomModel()：校验自定义模型是否启用且配置完整（projects.ts 本身不依赖 settings）
   │     ├─ 路径 1：OpenAI SDK（openai 依赖）+ stream:true
   │     ├─ 路径 2：回退直接 fetch `${baseUrl}/chat/completions` 手写 SSE 解析
   │     ├─ reasoning_content（思考）与 content（输出）分离统计
   │     ├─ content 为空且 finish_reason==='length' → max_tokens 32768 → 65536 升档重试
   │     └─ 每档尝试写入 userData/html-agent/chat.jsonl（含思考全文 / usage / 各阶段耗时）
   ├─ onProgress 映射为阶段文案 → win.webContents.send('project:html-progress', …)
   ├─ extractHtmlFromReply() 提取 HTML
   ├─ hfEnv.localizeGsapHtml() 把 GSAP CDN 引用改写为 ./gsap.min.js
   ├─ 引用本地时 copyGsapIntoProject() 落位；复制失败则 externalizeGsapHtml() 退回 CDN（宁可联网也不引用不存在的文件）→ 写回 index.html
   ├─ applyBgmToHtml() 按 project.audioFile 注入 <audio id="myv-bgm" src="audio/…" autoplay loop>（幂等；音频不进提示词）
   ├─ hfEnv.isHyperframesComposition() 校验（data-composition-id + GSAP __timelines）
   └─ 更新 htmlPath、置空失效的 videoPath，返回 { ok, htmlPath, compatible }
   ▼
渲染层刷新预览（project:preview-html → index.preview.html → <iframe src="hgpreview://…">）
   页面里的音轨由 HyperFrames CLI 在 trace 阶段 audio_process 提取并混入 MP4（应用侧不做 ffmpeg 混音）
```

### 5.2 语音转录

```
SubtitlePage/TranscribeSection.vue → whisperTools.transcribe({ … })
   ▼ whisper.ts
   prepareAudio()：非 whisper 可直接解码的格式先用内置 ffmpeg 转 wav（临时文件，用后清理）
   → vad.vadTrimSegments()：按采样做起止静音裁剪
   → spawn whisper-cli.exe（-m 模型 -f 音频 -oj JSON --no-prints -pp）
   → 解析 JSON 的 transcription.segments → opencc-js 繁转简 → 转成 [分:秒] 文本
   → 进度两阶段：先「正在加载模型」（不确定态），解析到 progress = N% 后转「转录中 N%」
   ▼ 返回 { text, subtitleText, segments, model }（不直接写盘）
渲染层弹窗选择「替换现有 / 追加到末尾」→ projectTools.saveSubtitle() 落盘 → 点亮「字幕」节点
```

### 5.3 转视频

```
HtmlGenPage/index.vue → hfTools.renderVideo(htmlPath, { quality, fps }) → video.ts
   ├─ 合规校验（非 HyperFrames composition 直接拒绝）
   ├─ 建工作目录 userData/hf-projects/html-video-<ts>/，整体复制素材
   ├─ 对渲染副本本地化 GSAP（localizeGsapHtml + 按需 copyGsapIntoProject，失败不阻断；不动用户原件）
   ├─ 定位：findHyperframesCli() + resolveNodePath()（避免 nvm shim / WindowsApps alias 下 spawn('node') 不稳定）
   ├─ 注入环境：FFmpeg bin 进 PATH，另设 HYPERFRAMES_FFMPEG_PATH / HYPERFRAMES_FFPROBE_PATH / PRODUCER_HEADLESS_SHELL_PATH
   ├─ spawn node hyperframes.mjs render -o output.mp4
   │      └─ 页面里的 <audio id="myv-bgm">（主进程注入的页面音轨）由 CLI 在 trace 阶段 audio_process 提取并混入 MP4；应用侧不做 ffmpeg 混音
   ├─ 渲染档位（质量 / 帧率）由渲染层随载荷传入，主进程按白名单拼 --quality / --fps（缺省走 CLI 默认 standard / 30）
   ├─ stdout/stderr 实时经 video:progress 回推（渲染层解析 [Render:trace] JSON 为中文阶段文案）
   └─ close 判定成功 → 返回 { outputVideo, projectDir, compatible }
发起方「HTML生成」页：成功后 projectTools.saveVideo() 回写 project.json + refreshProject()，并提示到「视频预览」页查看
「视频预览」页：内嵌播放成品 + 「在文件夹中显示」定位产物（纯预览页：成品由「HTML生成」页渲染并回写 `videoPath`）
```

### 5.4 字幕配音对齐（双模式）

- **模式 A（音频驱动）**：逐句 TTS 实测时长 → 重排字幕时间轴（音频不变速）。
- **模式 B（时间轴驱动）**：以字幕时间戳为槽位摆放配音，溢出时 `atempo` 加速（上限 `1.15`），仍放不下则顺延后续句子。
- 两者共用：逐句合成 → 24k 单声道 WAV → `ffprobe` 量时长；`buildTrack` 用静音补齐 + `concat -c copy` 零重编码装配整轨；进度经 `voice:align-progress` 回推，可经 `voice:align-cancel` 取消。

## 7. 安全边界

| 面 | 措施 | 位置 |
|---|---|---|
| 进程隔离 | `contextIsolation: true`、`nodeIntegration: false`，渲染层只能经 preload 白名单 API 访问系统能力 | `src/main/index.ts` |
| 本地文件预览 | 自定义 `hgpreview://` 协议（`standard` + `secure` + `supportFetchAPI` + `stream`），仅允许读取目标项目目录内文件，越界返回 403/404，并优先按 `previewMime` 显式给出 MIME | `src/main/index.ts` |
| iframe | 预览 iframe 使用 `sandbox="allow-scripts allow-same-origin"` | `src/renderer/src/pages/HtmlGenPage/`（项目 HTML 预览；「视频预览」页已改为纯 `<video>` 播放，不再有 iframe） |
| CSP | `index.html` meta：`default-src 'self'`，仅放行 `file:` / `hgpreview:` 的 frame 与媒体、`'unsafe-inline'` 样式，脚本禁 `unsafe-eval`（SFC 预编译）；dev 由 `cspDevWsPlugin` 追加实际 `ws://` 源 | `src/renderer/index.html`、`electron.vite.config.ts` |
| 注入 | 字幕等文本一律 `textContent` / `escTxt()` 写入，不拼 `innerHTML` | `src/renderer/src/utils/escape.ts` 及各页面 |
| 路径逃逸 | 项目内所有路径由 `projectDir()` 派生并做前缀校验；协议处理与 Agent 脚本各有独立的 `safePath` 校验 | `src/main/index.ts`、`src/main/projects.ts`、`src/agent/index.ts` |
| 密钥 | API Key 仅存本机 `userData/settings.json`，不外传；渲染层只读不落盘 | `src/main/settings.ts`、`src/main/voice.ts` |
| 外部程序 | 只调用随包携带的 `resources/` 内 node / ffmpeg / whisper-cli / HyperFrames，`spawn` 参数为数组形式不经 shell | `src/main/{hfEnv,video,whisper,ttsAlign}.ts` |
| 更新源 | 更新源地址可选（`settings.json` 的 `updater.feedUrl`，留空即用打包内置地址）；安装包经 electron-updater 校验 `sha512` 后才允许安装；`update:version` 走同步 IPC 但只回版本号字符串；失败文案分「用户可见 message / 排障 detail」两层，原始报错落 `userData/updater.log` 并可经 `update:open-log` 一键定位（该入口不依赖 electron-updater 能否加载） | `src/main/updater.ts`、`src/main/settings.ts` |
