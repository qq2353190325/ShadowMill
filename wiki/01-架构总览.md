# 01 · 架构总览

> 本文件描述应用的跨进程架构：进程模型与职责、IPC 契约全貌、以「项目」为中心的数据流、关键业务链路时序、安全边界与错误约定。

---

## 1. 进程模型

```
┌─────────────────────────────── Electron 应用 ───────────────────────────────┐
│                                                                             │
│  主进程 (src/main)                        渲染进程 (src/renderer)            │
│  ├─ index.ts   入口装配器                  ├─ index.html  宿主 + CSP         │
│  ├─ 业务域模块 register(ctx)               ├─ App.vue     外壳/菜单/Toast     │
│  ├─ 文件系统 / spawn / 对话框              ├─ pages/*/    8 个页面组件        │
│  ├─ http(s) 请求（Qwen / 模型 / 模型下载）  ├─ composables 全局状态/进度/提示  │
│  └─ 自定义协议 hgpreview://p / tts         └─ assets/main.css 设计系统        │
│                    ▲                                    ▲                   │
│                    │        preload 桥接层              │                   │
│                    └──── src/preload/index.ts ──────────┘                   │
│                         contextBridge 11 命名空间 + 6 进度通道                │
│                                                                             │
│  共享层 src/shared：ipc.ts / types.ts / errors.ts（错误文案映射）/ constants.ts │
│  独立脚本 src/agent：EOF 之外的实验 CLI，不进构建图、不打进包                  │
└─────────────────────────────────────────────────────────────────────────────┘
```

| 层 | 位置 | 职责 | 构建产物 |
|---|---|---|---|
| 主进程 | `src/main/` | 窗口与生命周期、运行环境（**分包**：ffmpeg / hyperframes 各成一个 7z、首次用到时下载并解到 `userData/runtime/<包名>/`；whisper 随安装包）的探测与解包、历史数据目录的归属证明与用户确认式处置（`legacy:*` 只给契约，界面在渲染层）、文件与目录读写、`spawn` 外部程序（whisper-cli / ffmpeg / HyperFrames / 7za）、全部网络请求、对话框、自定义协议 | `out/main/index.js`（CJS） |
| 桥接层 | `src/preload/` | 用 `contextBridge` 暴露受控 API；进度通道单订阅；`index.d.ts` 提供渲染层类型 | `out/preload/index.js`（CJS） |
| 渲染层 | `src/renderer/` | Vue 3 SFC 界面：外壳、菜单、8 个页面、全局设计系统；不直接触碰 Node/文件系统 | `out/renderer/`（`index.html` + `assets/*`） |
| 共享层 | `src/shared/` | IPC 频道名常量、跨进程载荷类型、**错误文案映射（`errors.ts`：原始报错 → 人话 + 配置分类）**，以及品牌等应用级公共常量（`constants.ts`）（编译期内联，无运行时产物） | 无（被打包进三端） |
| 实验脚本 | `src/agent/` | 独立 Tool Use Agent CLI，`node --experimental-strip-types` 直接运行 | 无（不进构建图） |

**进程数量**：全程单窗口（`mainWindow`）。窗口使用 `titleBarStyle: 'hidden'` 自绘标题栏，通过 `window:minimize` / `window:toggle-maximize` / `window:close` 三个 IPC 与主进程交互，最大化状态经 `window:maximized-change` 回推。

## 2. 启动时序

```
① 模块求值期（app ready 之前）
   ├─ USER_DATA_DIR = app.getPath('userData')   # 位置保持 Electron 默认（%APPDATA%\<package.json 的 name>），
   │                                      #   刻意不做 app.setPath，不做任何位置钉死
   ├─ writeIdentity(USER_DATA_DIR)        # 在当前 userData 落/更新归属标记 .shadowmill-data
   │                                      #   （{ appId: 'com.shadowmill.app', appName, dirName, at }；appId/dirName
   │                                      #    未变则跳过，幂等）——用于「归属证明」与将来改名后识别出这个目录
   ├─ mergeTree / pruneEmptyDirs / migrateFrom / findLegacyData / legacyInfo / resolveLegacy 定义
   │                                      #   legacyScanned / legacyFound：扫描结论缓存一次（MIGRATE_USER_DATA=0 时整段关闭）
   ├─ protocol.registerSchemesAsPrivileged([{ scheme: 'hgpreview', standard/secure/supportFetchAPI/stream }])
   │                                      #   紧随其后声明 TTS_PREVIEW_DIRS = ['tts-output','voice']
   │                                      #   （语音产物路由 ?tts=1 允许读的 userData 子目录白名单）
   └─ bootLog('main module loaded')      # 启动时序打点，写 userData/startup.log（下同）；STARTUP_LOG 在此解析一次并缓存
② app.whenReady()
   ├─ bootLog('app ready')
   ├─ protocol.handle('hgpreview', …)   # 预览文件协议；路由解析走 resolveHgPreviewPath(rawUrl)——判定按「段 + 查询标记」、不看 host：
   │                                    #   searchParams.get('tts') === '1'（现用写法）或 pathname 首段 === 'tts'（旧写法，兼容）
   │                                    #   ⇒ userData 下只读白名单；否则当项目名（pathname 首段）⇒ projects.projectDir()。两条都做目录穿越校验；
   │                                    #   → rangeResponse()（MIME 表 + Range 分片 206/416）→ 文件流返回；
   │                                    #   403（带 why）/ 404 / 500 写 userData/preview-protocol.log
   ├─ createWindow()                    # Menu.setApplicationMenu(null)、1200×800、hidden 标题栏、
   │                                    # backgroundColor '#0B1220'（与启动画面同色，首帧前不闪白）
   │                                    # contextIsolation:true / nodeIntegration:false / preload 指向 out/preload/index.js
   │                                    # dev 走 ELECTRON_RENDERER_URL，prod 走 loadFile('../renderer/index.html')
   │                                    # 另打点：window created → page load start → dom ready → page load finished → first paint
   ├─ ipcMain.handle('legacy:status', () => legacyInfo())          # 旧数据处置：主进程只回答「有没有 / 是什么」
   ├─ ipcMain.handle('legacy:resolve', (_e, action) => resolveLegacy(action))
   │                                    #   执行 迁移 / 删除 / 稍后（非法或缺省一律当 later）；界面由渲染层弹应用内弹窗
   │                                    #   —— 没有任何启动延迟，也不用原生 dialog.showMessageBox
   └─ 依次 register(ctx)：settings → projects → voice → ttsAlign → video → whisper → updater → runtime
                                        # ctx = { getWindow }，使各域对话框以主窗口为父
                                        # updater 注册后 3s 做一次启动静默检查
                                        # runtime 最后注册，**启动只探测、不下载**（缺包时推「运行环境需要下载（体积）」；排最后只保证 handler 先挂上）
                                        # 各域 register 只挂 IPC 与订阅；重模块（electron-updater / openai）懒加载
③ 渲染层
   ├─ index.html 的启动画面先上屏（纯 HTML/CSS，不等 JS）——填掉「窗口已出现、Vue 未挂载」的空背景
   └─ main.ts createApp(App).mount('#app')
      ├─ 挂载后：#boot-splash 加 .boot-done 淡出，300ms 后移除
      └─ App.vue onMounted
         ├─ window.windowControls.onMaximizedChange(...)   # 标题栏图标态
         ├─ initRenderProgress()                           # 订阅 video:progress
         ├─ initRuntime()                                  # 订阅 runtime:progress + 查一次 runtime:status（外壳横幅）
         ├─ initEnvGate()                                  # 不重复订阅：watch useRuntime 的状态（全渲染层只有 useRuntime.ts 注册 onProgress）+ 驱动「下载运行环境」确认框
         ├─ initLegacyData()                               # 问一次 legacy:status → 有旧数据就弹应用内弹窗
         │                                                 #   （此刻首屏已渲染完，故主进程侧无需任何延迟）
         └─ initApp()：
              localStorage['myapp.projectCtx'] 恢复当前项目
              → refreshProject()（project:list + project:load）
              → 首页已是初始页，不再调 goPage('home')（避免重复拉项目数据 + 首页重挂）
```

> **配置类弹窗（`useConfigPrompt`）没有 init 步骤**：它是模块级 `ref` 单例 + 由页面按需 `open()` / `fromResult()` 触发（与 `useEnvGate` 需要 `initEnvGate()` 订阅进度不同），`App.vue` 只负责把它渲染成 `.hf-modal`。因此启动链路上没有新增订阅。

> **历史数据目录（品牌改名的善后）怎么处理**（2026-10 定稿，本轮改为「界面在渲染层」）：userData 位置**保持 Electron 默认**（`app.getPath('userData')` = `%APPDATA%\<package.json 的 name>`，现 `shadowmill`，**没有 `setPath`**）。改名后老用户会看到「项目全没了」——数据其实还在 `%APPDATA%\my-app` 里。现在的做法是**扫描 + 弹窗让用户自己决定，绝不静默迁移**：`findLegacyData()` 扫 `LEGACY_DIR_NAMES`（现 `['my-app']`），四道闸依次为「排除自身 → 目录存在 → **归属证明通过** → 白名单条目确有数据（空壳不打扰）」，扫描结论由 `legacyInfo()` 缓存一次并经 `legacy:status` 交给渲染层；用户在**应用内弹窗**（`LegacyDataDialog.vue`，沿用 `.hf-modal` 体系）里选「迁移过来 / 删除旧数据 / 稍后再说」，选择经 `legacy:resolve` 回传、由 `resolveLegacy()` 执行（删除前会再校验目标确为 `%APPDATA%` 下清单内目录）。**主进程不做任何界面展示**：不再用原生 `dialog.showMessageBox`（与 Cyber UI 设计系统不一致），也**删掉了原先建窗后 1.5s 的 `setTimeout`**（显示时机由渲染层掌握，不需要「等首屏」的魔法数字）。迁移只搬 `OWN_DATA_ENTRIES`、目标不存在时整条目 `renameSync`、否则递归合并且**文件不覆盖**（唯一例外是仍处「出厂状态」的 `settings.json`，覆盖前先备份成 `.before-migrate.bak`），返回 `{ moved, skipped, failed }` 且**只有 `failed === 0` 才清缓存**（有失败可重试）。
> **归属证明（`isOurs`）**：`my-app` 这种名字太通用，`%APPDATA%` 下可能有别的应用也叫这个，所以先证明「它是我们的」——① 目录里**任意一个点开头的标记文件（名字不限）**内容里的 `appId` 等于常量 `APP_ID`（`'com.shadowmill.app'`）；② 否则看结构特征 `<目录>\projects\<项目名>\project.json` 是否存在（照顾标记机制上线之前的历史目录）。两条都不满足就**不提示、不迁移**。读取**只按内容认、不猜文件名**（`hasOurIdentity()`），因此改过多少次名都不会漏；写入仍用固定名 `.shadowmill-data`。
> **⚠ 代价**：`LEGACY_DIR_NAMES` 是**手工清单**，没有任何自动发现——以后改 `package.json` 的 `name` **必须**把旧名字加进去。另：业务模块的 userData 路径一律惰性求值（`projects.projectsRoot()` / `whisper.modelsDir()` / `runtime.runtimeDir()` / `settings.settingsFile()`）属**零代价的纯保险**（防将来有人重新引入 `setPath` 之类的改动）。完整算法与四道闸见 [files/main/index.ts.md](./files/main/index.ts.md) §3.1。

> **首屏慢的排查入口**：`userData/startup.log` 每行带「距进程启动的毫秒数」，可区分时间花在主进程模块加载、建窗、还是页面加载（历史数据的迁移 / 删除 /「稍后再说」也写在同一文件的一行里）；渲染层的可见反馈由 `src/renderer/index.html` 的启动画面提供。详见 [files/main/index.ts.md](./files/main/index.ts.md) §3.3 / §5 与 [files/renderer/index.html.md](./files/renderer/index.html.md) §2.2。

## 3. IPC 契约

### 3.1 四种通信形态

| 形态 | 主进程侧 | preload 侧 | 用途 |
|---|---|---|---|
| 请求/响应 | `ipcMain.handle(channel, fn)` | `ipcRenderer.invoke(channel, payload)` | 绝大多数业务调用（返回 `IpcResult`） |
| 同步取值 | `ipcMain.on(channel, fn)` + `event.returnValue` | `ipcRenderer.sendSync(channel)` | 仅 `update:version`（首屏要立刻显示版本号） |
| 单向指令 | `ipcMain.on(channel, fn)` | `ipcRenderer.send(channel)` | 窗口控制、取消对齐 |
| 进度推送 | `win.webContents.send(channel, data)` | `ipcRenderer.on(channel, cb)` 经命名空间回调转发 | HTML 生成、whisper、配音对齐、视频渲染、应用更新、运行环境包（`legacy:*` 刻意没有推送：结论由渲染层主动拉取） |
| 状态回推 | 同上 | 同上 | 窗口最大化状态变化 |

> 页面资源（预览 iframe / 素材缩略图 / 视频 / 音频）**不走 IPC**：它们走主进程注册的自定义协议 `hgpreview://`，见 §7「安全边界」。

### 3.2 preload 的 11 个命名空间

| 命名空间 | 覆盖域 | 对应主进程模块 |
|---|---|---|
| `electronAPI` | `platform`、`versions`（node/chrome/electron） | 无（纯数据） |
| `appTools` | 剪贴板复制 | `src/main/index.ts` |
| `windowControls` | 最小化 / 最大化切换 / 关闭 / 最大化状态订阅 | `src/main/index.ts` |
| `hfTools` | HTML 预览与 HyperFrames 转视频 | `src/main/video.ts` |
| `settingsTools` | 自定义模型设置与连接测试、渲染档位、更新设置 | `src/main/settings.ts` |
| `voiceTools` | 语音服务（音色管理、文字生音频、字幕配音对齐；**按厂家**取端点与 Key，目录见 `voiceCatalog.ts`） | `src/main/voice.ts` / `voiceCatalog.ts` / `ttsAlign.ts` |
| `whisperTools` | whisper.cpp 转录与模型管理 | `src/main/whisper.ts` |
| `projectTools` | 项目化流水线（字幕 / 内容脚本 / HTML / 视频 / 音频） | `src/main/projects.ts` |
| `updateTools` | 应用自更新：检查 / 下载 / 取消 / 重启安装 / **状态查询（`status`）** / **打开日志** / **查看更新日志（`changelog`）** + 进度订阅 | `src/main/updater/`（目录 4 文件，出口 `updater/index.ts`） |
| `runtimeTools` | 运行环境（分包 ffmpeg / hyperframes）：状态查询 / 主动准备（`prepare(packs?)`）/ **取消（`cancel`）** / 进度订阅 | `src/main/runtime.ts` |
| `legacyTools` | 旧版本数据：状态查询（`status`）/ 回传选择（`resolve`）；**无推送订阅** | `src/main/index.ts` |

**Update（`updater/index.ts` 作统一出口，实现在 `src/main/updater/` 的 base / actions / install 三个子文件，electron-updater generic provider）**

| 频道 | preload | 说明 |
|---|---|---|
| `update:check` | `updateTools.check()` | 检查更新（读更新源 `latest.yml` 对比 `app.getVersion()`）；返回体带主进程产出的 `message` + 排障用 `detail`。**检查必须「有事件才算成功」**：electron-updater 在「未打包且未强制 dev」时直接 `return null`、或已有检查在飞时复用旧 Promise，两种情形都不发任何事件，`checkNow()` 因此报成功前判一次 `state.stage` 是否仍是 `checking`，是则落 `error` 并把「开发环境不检查更新」（未打包）/「检查更新失败，请稍后重试」送到界面；`update:download` 侧同理：resolve 后既无进度也无 `update-downloaded` ⇒ 「下载没有开始，请稍后重试」 |
| `update:download` | `updateTools.download()` | 下载安装包（`autoDownload = false`，仅用户触发；带差分下载） |
| `update:cancel` | `updateTools.cancel()` | 取消下载 |
| `update:install` | `updateTools.install()` | 退出并运行安装器（有转录 / 渲染 / 配音任务在跑时拒绝） |
| `update:version` | `updateTools.version()` | **同步**（`sendSync`）返回当前版本号，供设置页首屏显示 |
| `update:status` | `updateTools.status()` | 取一次主进程当前更新状态（`payload()` 快照，`stage` 经白名单收敛）；主进程状态常驻——设置页挂载时用它补出「启动静默检查」那次失败（该事件发生在页面订阅 `update:progress` 之前） |
| `update:open-log` | `updateTools.openLog()` | 在文件管理器里定位 `userData/updater.log`（没有日志则打开 `userData` 目录）；**刻意不经过 electron-updater 的懒加载**，加载失败时也能取证；设置页只在更新确实出错时才露出这个入口（`updateLogVisible`） |
| `update:changelog` | `updateTools.changelog()` | 取随包 `CHANGELOG.md` 的**原文**（`readBundledChangelog()` → `app.getAppPath()/CHANGELOG.md`，该文件已列进 `package.json` 的 `build.files` 随包进 asar）；**主进程只定位 + 读取、不做解析**——分块与行内排版在渲染层 `src/renderer/src/utils/changelog.ts`，界面是设置页「应用更新」的「查看更新日志」弹窗；与 `open-log` / `status` 一样**不经过 electron-updater 的懒加载** |
| `update:progress` | `updateTools.onProgress(cb)` | 主→渲染，更新阶段 / 下载进度（载荷含 `message` 与可选的 `detail`） |

**Runtime（`runtime.ts`，运行环境分包）**

| 频道 | preload | 说明 |
|---|---|---|
| `runtime:status` | `runtimeTools.status()` | renderer → main，`invoke`；查询运行环境状态（`phase` / `pack` / `missing` / `status` / `percent` …） |
| `runtime:prepare` | `runtimeTools.prepare(packs?)` | renderer → main，`invoke`；主动准备指定包（省略 = 全部缺的）。**参数必须是普通数组**（渲染层 `toRaw(list).slice()`）：`invoke` 的参数要过结构化克隆，Vue 响应式 `Proxy` 会抛 `DataCloneError`、主进程 handler 根本不执行；忙碌期重复调用回一句提示，非 ok 回执 / 抛错由渲染层 `prepare()` 写进状态（不再静默） |
| `runtime:cancel` | `runtimeTools.cancel()` | renderer → main，`invoke`；**取消**进行中的**检查 / 下载 / 解包**（中断 HTTP 请求与 `7za` 子进程，并清半成品；取清单 20 秒无响应属**超时**、不算取消，残片保留待续传） |
| `runtime:progress` | `runtimeTools.onProgress(cb)` | main → renderer，`send`；运行环境进度推送（单订阅；外壳横幅与确认框都消费它） |

### 3.4 结果约定

- 业务类 `invoke` 统一返回 `{ ok: true, ...数据 }` 或 `{ ok: false, message, detail?, canceled? }`（`src/shared/types.ts` ① 节的 `IpcFail` / `IpcResult<T>`；`message` 为可选，取消分支只有 `canceled: true`）；取消类对话框以 `canceled: true` 表达，UI 侧不弹错误。
- **失败分支还有两组可选字段**：`needPacks?: RuntimePackName[]`（运行时缺包，`'ffmpeg'` / `'hyperframes'`）与 `needConfig?: ConfigTarget`（`'model' | 'voice'`，**配置类**错误）+ `title?: string`（弹窗标题）。两者语义不同：`needPacks` **要续做**（用户在确认框里点「继续」后原参数重发），`needConfig` **不驱动流程**，只是把「这个错误该去哪修」交给界面分流。**余额 / 欠费刻意不给 `needConfig`**（去设置修不了余额），它走内嵌状态行。
- **`message` 与 `detail` 分两层**：`message` 是给终端用户的人话（发生了什么 + 能做什么），`detail` 是可选的排障信息（原始报错 / HTTP 状态 / 请求地址），由 UI 的「查看详情」折叠展示。目前主要落在 `update:*` 一族（`UpdateCheckResult.message` 为必填、`detail` 可选；`UpdateProgressPayload.detail` 仅 `error` 阶段非空；`update:changelog` 的失败分支同理——文件缺失回 `没有找到更新日志文件` + 期望路径，读取失败回 `读取更新日志失败` + 原始异常），详见 [files/main/updater.md](./files/main/updater.md) §5 的文案对照表。**例外**：更新族另有两条 `error` 文案（「开发环境不检查更新」/「下载没有开始，请稍后重试」）由 `checkNow()` / `downloadUpdate()` 的「无事件守卫」手写成对写下，不经 `humanError()`——它们不是报错，没有原始异常可抠。
- **「英文原始报错 → 人话文案」的唯一映射表是 `src/shared/errors.ts`**（纯函数、无副作用、不 import electron）：`friendlyError(err, ctx)` 按固定顺序分十档判定（余额/欠费 → 未启用/未配置 → 鉴权 401/403 → 地址或模型不存在 404/405 → 限流（配额耗尽先于 429）→ 5xx → 内容合规 → 参数 400/422 → 网络 errno → 文件系统 errno → 兜底），产出 `message`（始终带 `label：` 前缀）、`detail`（原始报文首行截断 500 字符 + `extras`）、以及配置类的 `needConfig` / `title`。接入点是 `htmlAgent.ts` / `settings.ts` / `voice.ts`（`voiceFriendlyError` 变成它的薄包装，并把 `detail` 追加回文案）；`projects.ts` 在「只剩一句已翻译中文文案」时用 `configTargetOf()` 复用同一张码表补分类。**全应用只有这一处码表**（`updater/base.ts` 的 `humanError()` 是同一分层约定、但只服务自更新链路，故未合并）。详见 [files/shared/errors.ts.md](./files/shared/errors.ts.md) 与 `docs/error-mapping.md`。
- **配置类错误在渲染层的升级**：拿到 `res.needConfig` 后由 `useConfigPrompt`（模块级单例）弹 `.hf-modal`（**主按钮固定「去设置」**、次按钮「取消」），**刻意不显示「查看详情」**；`needConfig` 为假的失败仍按原样走内嵌状态行 / toast。设置页的「测试连接」刻意不弹（按钮与状态行都在本页，弹「去设置」等于原地跳）。
- 少数查询类接口直接返回数组/对象（`project:list`、`project:load`、选择文件类返回 `string | null`）。
- 进度通道为**单订阅**语义：preload 用模块级 `_xxxProgressCb` + `_xxxProgressBound` 标志，重复注册只替换回调，避免页面切换叠加监听。

## 4. 以「项目」为中心的数据流

```
                    ┌───────────────────────────────────────────┐
                    │  userData/projects/<项目名>/project.json   │
                    │  { title, subtitle, content,              │
                    │    render, canvas, audioFile, htmlPath,   │
                    │    videoPath, materials }                 │
                    │  videoPath 存项目内相对路径                 │
                    │  （video/output.mp4）——就地渲染的产物       │
                    └───────────────────────────────────────────┘
                          ▲            ▲             ▲
   渲染层全局状态           │            │             │
   useAppStore.appState     │            │             │
   （currentName/project/   │            │             │
     myProjects）           │            │             │
        │                   │            │             │
        ├─ ① 音色管理 ───────┼────────────┼─────────────┼─→ settings.json（voice 段：按厂家的 apiKey + voiceProfiles 本地映射）
        │                   │            │             │     千问云端（克隆音色）
        ├─ ② 文字生音频 ─────┼────────────┼─→ audio/ ───┘     （audioFile 写入 project.json）
        │                   │            │
        ├─ ③ 文字转字幕 ─────┼─→ subtitle.txt                （手写 / 脚本旁白 / whisper 转录）
        │                   │            │
        ├─ ④ 字幕生成 HTML ──┼────────────┴─→ index.html       （含主进程注入的 <audio id="myv-bgm"> 音轨；+ index.preview.html 预览副本）
        │                   │
        └─ ⑤ 视频预览 ───────┴──────────────→ video/output.mp4  （转视频入口在 ④ 页；成品**就地生成在项目内**，`videoPath` 以相对路径回写 project.json，`project:load` 取出时再换算成绝对路径）
```

- 每个页面/组件通过 `useAppStore` 的 `appState.project` 读取当前项目；任何写操作落盘后调用 `refreshProject()` 重新拉取，`hasContent / hasAudio / hasSubtitle / hasHtml / hasVideo` 五个 computed 驱动 `StepBar` 的点亮状态。
- 当前项目上下文持久化在渲染层 `localStorage['myapp.projectCtx']`（只存 `{ name }`），prod 下 `file://` 同源，重启后自动延续。
- **项目只有一种形态**：`userData/projects/<项目名>/` 下用户自建、可读可写的普通项目；`hasContent` / `hasAudio` / `hasSubtitle` / `hasHtml` / `hasVideo` 五个 computed 一律只看当前项目自身的产物字段（`hasHtml` 额外要求 `htmlExists && htmlPath` 同时成立）。
- **`userData` 本身的绝对位置**：`%APPDATA%\<package.json 的 name>`（现 `%APPDATA%\shadowmill`，Electron 默认语义，`index.ts` 不做 `setPath`），因此上面的相对路径在**同一次改名之间**保持稳定；改名导致目录变化时，由启动时的「归属证明 + 用户确认式迁移」把老目录内容搬过来（用户点「迁移过来」才搬）。
- **项目素材库（图片 / 视频）的链路**：添加素材（`project:pick-media` 选文件 → `project:add-materials` 复制进 `images/` / `video/` 并在 `project.json` 的 `materials` 里登记一条 `ProjectMaterial`）→ 在素材卡片墙上勾选（`selected`，经 `project:save-materials` 整份回写）→ 生成 / 修改时提交 `materialIds` → 主进程 `resolveMaterials()` 按 id 过滤、`buildMaterialBlock()` 拼「【图片素材】/【视频素材】」两段提示词 → 模型在 HTML 里写 `<img src="images/…">` / `<video src="video/…">`（**项目内相对路径**：预览经 `hgpreview://` 取，转视频时同目录相对引用同样成立）。
  - 素材的**存在形态**只有两个：`project.json` 里的一条登记（`id` / `kind` / `file` / `label` / `selected` / `addedAt`）与项目目录里的文件；渲染层（[`useAppStore.ProjectState.materials`](./files/renderer/src/common.md)）与主进程（`normalizeMaterials()`）读的是同一份结构。
  - **上限与白名单只有一处**：`src/shared/constants.ts` 的 `MAX_MATERIALS = 20`（图片 + 视频**合计**）/ `IMAGE_MATERIAL_EXTS` / `VIDEO_MATERIAL_EXTS`；主进程负责准入与截断，渲染层只用它显示 `n / 20` 与支持格式。
  - **移除 ≠ 删除**：`project:save-materials` 只摘掉登记，项目目录内的文件保留（卡片上的「移除」按钮 `title` 已向用户说明）。
- **「路径 → URL」在本轮收口到一处**：渲染层不再各自拼 `file://` 或 `hgpreview://`，一律走 `src/renderer/src/utils/url.ts` 的 `previewUrl(项目名, 相对路径, bust?)`（项目内资源）与 `ttsUrl(绝对路径)`（项目外语音产物）；`ttsUrl()` 认不出白名单目录时返回空串，调用方据此不给试听入口。详见 [common.md](./files/renderer/src/common.md) §7.3。

## 5. 关键业务链路

### 5.1 HTML 生成（最复杂的一条链路）

> 两个频道都不要写混：**界面上是两个并列的按钮**——「生成 HTML」走 `project:generate-html`（提示词**不含**现有页面），「按需求修改」走 `project:modify-html`（提示词把当前 `index.html` 全文置于最前）；没有 HTML 时「按需求修改」按钮禁用。**「生成 HTML」点一次即执行、没有二次确认**（已有 HTML 时直接覆盖，按钮文案恒为「生成 HTML」），走的仍是 generate、忽略现有页面。两个 handler 各自独立、**没有合并**，下面以 generate 为例画链路，modify 除提示词多一段现有源码外其余步骤一致（见 [files/main/projects.ts.md](./files/main/projects.ts.md) §5.2 / §5.3）。


### 5.3 转视频

```
HtmlGenPage/index.vue → hfTools.renderVideo(htmlPath, { quality, fps, canvas }) → video.ts
   ├─ 缺包纯校验：runtime.missingPacks(['ffmpeg','hyperframes'])，缺包回 needPacks 由界面确认下载（不阻塞）
   ├─ 合规校验（非 HyperFrames composition 直接拒绝）
   ├─ 就地渲染：渲染根 cwd = HTML 所在的项目目录（不再建 hf-projects 工作目录、不复制素材），
   │     入口写 <项目目录>/.render-tmp/entry.html（GSAP 引用改写为 ../gsap.min.js，落盘前先清残留；
   │     并把项目画布写成根节点 data-resolution —— applyCanvasDeclaration，不写就会被 CLI 兜底成 portrait）
   ├─ 裁定成片时长：① <html data-composition-duration> 声明 → ② 无头 Chromium 现场量 GSAP 时间轴
   │     （chrome 取 BUILTIN_RESOURCES.chromeShell，与渲染共用；--dump-dom 读回，口径同预览 clock()）
   │     → ③ 都拿不到就交给 CLI 按最长媒体裁定；裁定结果写 userData/video-duration.log
   ├─ 裁超长媒体副本：规则是「成片时长 = max(声明, 最长媒体)」，声明只能往上顶 ⇒ 用
   │     ffmpeg -c copy -t <时长> 把超长媒体裁成 .render-tmp/media/<文件>（**只裁副本、原件不动**）
   │     并改写入口里的 src 为 ./media/<文件>；<0.25s 差值不裁
   ├─ 定位：findHyperframesCli() + findNode()（返回 { cmd, env }，避免 nvm shim / WindowsApps alias 下 spawn('node') 不稳定）
   ├─ 注入环境：ffmpeg bin 进 PATH，另设 HYPERFRAMES_FFMPEG_PATH / HYPERFRAMES_FFPROBE_PATH / PRODUCER_HEADLESS_SHELL_PATH
   ├─ spawn node hyperframes.mjs render -c .render-tmp/entry.html -o <项目目录>/video/output.mp4（cwd = 项目目录）
   │      └─ 页面里的 <audio id="myv-bgm">（主进程注入的页面音轨）由 CLI 在 trace 阶段 audio_process 提取并混入 MP4；应用侧不做 ffmpeg 混音
   ├─ 渲染档位（质量 / 帧率）由渲染层随载荷传入，主进程按白名单拼 --quality / --fps（缺省走 CLI 默认 standard / 30）
   ├─ stdout/stderr 实时经 video:progress 回推（渲染层解析 [Render:trace] JSON 为中文阶段文案）
   └─ close：先删掉 .render-tmp/（无论成败）→ 成功则返回 { outputVideo: <项目目录>/video/output.mp4, projectDir, compatible }
发起方「HTML生成」页：成功后 projectTools.saveVideo() 把成品路径**换算成项目内相对路径**回写 project.json + refreshProject()，并提示到「视频预览」页查看
「视频预览」页：经 hgpreview:// 协议内嵌播放成品 + 「在文件夹中显示」定位产物（纯预览页：成品由「HTML生成」页渲染并回写 videoPath，取用时由 project:load 换算成绝对路径；URL 由 utils/url.ts 的 previewUrl() 拼、file:// 分支已删除）
```

### 5.4 字幕配音对齐（双模式）

- **模式 A（音频驱动）**：逐句 TTS 实测时长 → 重排字幕时间轴（音频不变速）。
- **模式 B（时间轴驱动）**：以字幕时间戳为槽位摆放配音，溢出时 `atempo` 加速（上限 `1.15`），仍放不下则顺延后续句子。
- 两者共用：逐句合成 → 24k 单声道 WAV → `ffprobe` 量时长；`buildTrack` 用静音补齐 + `concat -c copy` 零重编码装配整轨；进度经 `voice:align-progress` 回推，可经 `voice:align-cancel` 取消。
- 产物落 `userData/voice/align-<时间戳>/`（**项目外**），试听源由渲染层 `ttsUrl()` 换算成 `hgpreview://tts/…?tts=1`（不再是 `file://`）；逐句试听拿不到可预览 URL 时提示「这一句的试听文件不在可预览目录里」，播放失败文案是「对齐任务目录可能已被清理」。
- 失败分支：`AlignSection` 先判 `useConfigPrompt().fromResult(fail)`（配置类优先，弹「去设置」），再判 `needPacks`（缺 ffmpeg 弹环境确认框，点「继续」重发），都不是才 toast。

## 7. 安全边界

| 面 | 措施 | 位置 |
|---|---|---|
| 进程隔离 | `contextIsolation: true`、`nodeIntegration: false`，渲染层只能经 preload 白名单 API 访问系统能力 | `src/main/index.ts` |
| 本地文件预览 | 自定义 `hgpreview://` 协议（`standard` + `secure` + `supportFetchAPI` + `stream`），路径解析由独立函数 **`resolveHgPreviewPath(rawUrl)`** 承担（返回 `{ full, why }` 或 `null`），**两条分支**：`hgpreview://p/<项目名>/<相对路径>` 仅允许读目标项目目录内的文件（`p` 在 host 位，不剥 `p/`）；`hgpreview://tts/<相对路径>?tts=1`（本轮新增）仅允许读 userData 下 `TTS_PREVIEW_DIRS = ['tts-output','voice']` 白名单目录内的文件——**不在白名单即 403**（`why = not-in-whitelist:<top>`）、穿越即 403（`why = traversal`），两条分支都做目录穿越校验（`full === dir \|\| full.startsWith(dir + path.sep)`）；403 / 404 / 500 一律写 `preview-protocol.log`。**路由判定按「段 + 查询标记」、不看 host**：`searchParams.get('tts') === '1'` 或 `pathname` 首段为 `tts`（旧写法兼容）——当初把 `tts` 放 host 位时 `pathname` 取不到它、会被当成项目名而 404（已修，注记见 [02-目录架构-src-main.md](./02-目录架构-src-main.md) §4.1）。MIME 由 `previewMime` 按扩展名显式给出；响应统一由 `rangeResponse()` 构造，**支持 `Range` 字节范围取**（`206` + `Content-Range` / 非法范围 `416` + `bytes */size`，无 `Range` 为 `200`；`HEAD` 只回头），响应体是 `fs.createReadStream` → `Readable.toWeb()` 的文件流（`Accept-Ranges: bytes` + `Cache-Control: no-store`）。**页面消费方四类**：HTML 预览 iframe（`PreviewSection.vue` 的 `loadFrame()`）、素材缩略图 `<img>`（`MaterialsSection.vue` 的 `thumbUrl()`）、视频预览页的 `<video>`（`VideoPreviewPage/index.vue` 的 `toHgPreviewUrl()`）、**音频试听 `<audio>`（`PreviewSection.vue` 的背景音频、`SynthSection.vue` / `AlignSection.vue` 的语音产物试听——本轮新增）**；URL 一律由 `src/renderer/src/utils/url.ts` 的 `previewUrl()` / `ttsUrl()` 拼装（**逐段 `encodeURIComponent`**，与处理器逐段 `decodeURIComponent` 对应），渲染层不再出现 `file://` 拼接 | `src/main/index.ts`、`src/renderer/src/utils/url.ts` |
| iframe | 预览 iframe 使用 `sandbox="allow-scripts allow-same-origin"` | `src/renderer/src/pages/HtmlGenPage/`（项目 HTML 预览；「视频预览」页是纯 `<video>` 播放、没有 iframe，**其播放源也走 `hgpreview://`**——原 `file://` 拼接已删除，因为 dev 下渲染页在 `http://localhost`、Chromium 拒绝 http 页读 `file://` 视频） |
| CSP | `index.html` meta：`default-src 'self'`，仅放行 `file:` / `hgpreview:` 的 frame 与媒体、`'unsafe-inline'` 样式，脚本禁 `unsafe-eval`（SFC 预编译）；dev 由 `cspDevWsPlugin` 追加实际 `ws://` 源 | `src/renderer/index.html`、`electron.vite.config.ts` |
| 注入 | 字幕等文本一律 `textContent` / `escTxt()` 写入，不拼 `innerHTML` | `src/renderer/src/utils/escape.ts` 及各页面 |
| 路径逃逸 | 项目内所有路径由 `projectDir()` 派生并做前缀校验（`project:delete` 用 `dir.startsWith(projectsRoot())`）；协议处理与 Agent 脚本各有独立的 `safePath` 校验 | `src/main/index.ts`、`src/main/projects.ts`、`src/agent/index.ts` |
| 数据目录归属 | userData 位置保持 Electron 默认（跟随 `package.json` 的 `name`，无 `setPath`）；迁移前先做**归属证明**（`isOurs`：点开头的标记文件内容 `appId` 一致，或 `projects\<项目名>\project.json` 结构特征），不通过就**不提示、不迁移**（挡住重名应用）；迁移只搬白名单条目且**文件不覆盖**（`settings.json` 例外需仍处「出厂状态」且覆盖前备份），删除前还会二次校验目标确为 `%APPDATA%` 下清单内目录 | `src/main/index.ts`、`src/main/settings.ts` |
| 密钥 | API Key 仅存本机 `userData/settings.json`，不外传；渲染层只读不落盘 | `src/main/settings.ts`、`src/main/voice.ts` |
| 错误文案 | 原始英文报文**不进用户文案**：`friendlyError()` 只把「人话 + 可做什么」放进 `message`，状态码 / 厂商 code / 请求地址一律只进 `detail`（配置类弹窗连 `detail` 都不显示） | `src/shared/errors.ts` 及各 `catch` 分支 |
| 外部程序 | 只调用「安装包内的 `resources/whisper`（whisper-cli）与 `resources/tools`（7za）」和「运行环境包解出的 `<userData>/runtime/<包名>/`（ffmpeg / HyperFrames）」；`spawn` 参数为数组形式不经 shell（Node 例外：优先复用 Electron 内嵌 Node） | `src/main/{hfEnv,video,whisper,ttsAlign}.ts` |
| 更新源 | 更新源地址可选（`settings.json` 的 `updater.feedUrl`，留空即用打包内置地址）；安装包经 electron-updater 校验 `sha512` 后才允许安装；`update:version` 走同步 IPC 但只回版本号字符串；失败文案分「用户可见 message / 排障 detail」两层，原始报错落 `userData/updater.log` 并可经 `update:open-log` 一键定位（该入口不依赖 electron-updater 能否加载） | `src/main/updater/`（出口 `updater/index.ts`）、`src/main/settings.ts` |

> **为什么以前 `'file:///' + encodeURI(path)` 能用（本轮改动的背景，务必记住）**：旧版 `createWindow()` 用 `mainWindow.loadFile(...)`，**dev 与生产都是 `file://` 源**，所以渲染层直接拼 `file://` 读本地音频 / 视频在当时确实成立（旧树里十余处，Vue 化时整段照搬）。`9615eaf`（electron-vite 重构）引入 `if (process.env['ELECTRON_RENDERER_URL']) loadURL(...) else loadFile(...)` 之后，**dev 渲染页变成 `http://localhost` 源**，Chromium 拒绝 http 页读 `file://`，5 处音频试听因此在 dev 下**静默失效**（打包版仍可用），其中 `AlignSection` 的兜底文案还把它误报成「临时文件被清理」。这就是本轮「路径 → URL 收口 + 音频预览改走 `hgpreview://`」的由来（CHANGELOG #25 / #26 / #27）。**唯一保留的 `file:///`** 在主进程 `src/main/video.ts:77`：它喂给 Chromium `--dump-dom` 量 GSAP 时间轴，**不在页面里、不受同源策略约束**，因此不属于页面资源，也不改。
